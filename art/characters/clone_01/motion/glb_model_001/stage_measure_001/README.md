## ② 좌표 규약

- 단위: 캐릭터 단위(= Blender 단위, 키 약 1.0 ≈ 1.65m). 스프라이트는 200px/단위다.
- 기준: 매니페스트 `originX`(발 앞뒤 기준, 월드 Y = 0)·`groundY`(바닥, 월드 Z = 0). 측정한 18개 동작은 모두 `originX` 144, `groundY` 272(300px 캔버스 기준)다.
- 오른쪽을 볼 때 잘린 프레임 이미지 안의 픽셀:
  `px = originX − crop.x + x × 200`, `py = groundY − crop.y − y × 200` (y는 아래로 증가)
- 왼쪽을 볼 때(좌우 반전): 월드 x = 발 x − 앞 x, 높이는 그대로. 총구 각도는 위(+)가 그대로이고 방향만 반대다.
- JSON `frames[gun][k] = [x, y, pitch3d, screenPitch]`. k는 스프라이트 프레임 번호(0부터, 30fps), pitch는 도(+가 위). `null`은 그 프레임에 무기가 숨어 있음(크기 0)이다. 측정한 동작에서는 숨김 프레임이 없었다. 소총 동작의 권총, 쌍권총 동작의 소총은 JSON에서 뺐다.
- 앞 x는 Blender의 −Y, 높이 y는 Blender의 Z다. 화면 깊이(Blender X)는 쓰지 않는다.

## ③ 방법·정확도

- **샘플링:** `render_glb_sprites.py --fps 30`과 같다. 같은 import, 최상위 오브젝트를 `sprite_root` 아래에 두고, 동작과 슬롯 0을 지정한다. 실제 키 범위에서 0.8프레임 간격(소수 누적 오차 포함)으로 샘플하고, 루프·closed·원샷 끝 규칙과 엉덩이 제자리 보정도 같다. 각 동작은 스프라이트를 렌더한 GLB에서 쟀다(sprite_004 ← loadout_023, 005 ← 027, 006 ← 029, 007 ← 030).
- **검증 결과**
  - 매니페스트 `frameCount`: 18개 모두 샘플 수와 일치.
  - 메시 투영 상자와 스프라이트 알파: 프레임별 PNG 알파 상자와 1px 안으로 일치(gunplay 전 19프레임, rifle_aim_idle 11개 표본 프레임). 클립 전체 crop과는 −2.1~+2.0px로, crop의 +1px 여백과 가장자리 반투명만큼이다.
  - loadout_030과 비교: 18개 동작 모두 총구 위치 차이가 0.0이다. 프로토타입이 쓰는 새 버전과 같다.
  - 총구 점과 그림 비교: 총신 방향으로 마지막 불투명 픽셀까지의 거리를 쟀다. 조준·사격 동작의 소총과 왼쪽 권총은 중앙값 0~0.4px, 전 프레임 ±1.5px 안이다. 낮춘 소총(rifle_idle·walk·run)은 +1.8~3px, 오른쪽 권총은 일부 프레임에서 최대 6px로 나왔다. 확인 이미지를 보면 총구 점은 총 끝에 있고, 그 너머로 다리·몸·왼쪽 권총이 겹쳐 생긴 값이다.
- **총구 점 정의:** 무기 메시 자체 정점만 쓴다(소총의 탄창·노리쇠 자식 메시 제외). 가장 긴 로컬 축은 세 무기 모두 +X다(glb-gun-fx.js와 같음). 그 끝에서 길이 1.8% 안 정점들(소총 512개 · 약 0.009단위, 권총 약 250개 · 약 0.003단위)의 상자 중심을 쓰고, 총신 축 값은 끝 값이다. 실제 총구 구멍과는 mm~수 mm(1px 안) 차이가 날 수 있다. glb-gun-fx.js는 축 방향으로 0.002를 더 내미는데 여기서는 더하지 않았다(0.4px).

## ④ 발사 프레임 규칙

스프라이트 프레임 k는 첫 키 기준 시각 k/30초다. 원본 24fps 프레임 = 첫 키 + 0.8k.

| 동작 | 실제 반동 시작 (원본 프레임) | 스프라이트 위치 | 첫 키 기준 시각 | 판단 |
|---|---|---|---|---|
| `gunplay` (첫 키 1) | 3 | 2.5 (2와 3 사이) | 0.083초 | 3D 뷰어 cue 3/24초(절대 시각)와 일치 |
| `gunplay_auto` (첫 키 1) | 2 | 1.25 | 0.042초 | 뷰어 cue 2/24와 일치 |
| `shoot_rifle` (첫 키 1) | 5 | 5 | 0.167초 | 뷰어 cue 5/24와 일치 |
| `dual_fire` (첫 키 1) | 오른쪽 1·13, 왼쪽 7·19 | 0 · 7.5 · 15 · 22.5 | 0 · 0.25 · 0.5 · 0.75초 | cue i/4를 **첫 키 기준**으로 셀 때 일치. 뷰어 절대 시각으로는 1/24초 이르다 |
| `rifle_full_auto` (첫 키 0) | 총구 각도 반동 없음 | 0.6 + 2.4i (i = 0~19) | 0.02 + 0.08i초 | 각도 검출 불가. cue 시각을 그대로 쓴다 |

- **cue 시각 두 해석:** glb-gun-fx.js의 cue는 three.js 재생 시각, 즉 glTF 절대 시각이다. 대부분의 동작은 키가 1프레임(1/24초)에서 시작하므로 첫 키 기준과 1/24초 차이가 난다.
  - 소총 단발 3개는 절대 시각이 실제 반동과 맞는다.
  - `dual_fire`는 첫 키 기준이 맞는다(제작 도구 `make_dual_pistol_clips.py`의 `SHOTS` 1·7·13·19와 같음).
  - JSON `cues[]`에는 두 해석(`startRelative`, `viewerAbsolute`)의 직전·직후 프레임 번호와 그 정확한 시각의 총구 위치를 모두 넣었다.
- **FIRE_KICK 비교:** `attach_weapon.py` 규칙(프레임당 1.5° 이상 오르기 직전, |각도| ≤ 25°)으로는 `gunplay_auto` 2, `shoot_rifle` 5, `dual_fire` 1·7·13·19가 위와 같게 나온다.
  - `gunplay`는 최대 상승률이 1.43°/프레임이라 검출되지 않는다. 0.5°/프레임으로 낮춘 같은 규칙에서 3이 나온다(`softSourceFrames`).
  - `rifle_full_auto`는 총구 각도 변화가 최대 0.34°라 어느 기준으로도 검출되지 않는다(full_auto_005에서 총구를 수평으로 고정했기 때문).
  - 오검출: `rifle_run` 1·14(달리기 팔 흔들림), `dual_aim_to_ready` 5·6(올리고 내리는 동작)은 사격이 아니다.
- **프로토타입 적용 제안**
  - 소총 단발: 스프라이트 2.5프레임(0.083초)이 반동 시작이다. 반동 최고점은 프레임 5(0.167초)다. 기획 메모의 “0.63초에 1발”은 클립 길이이고 실제 발사 프레임이 아니다. v1의 `limit=0.10`은 발사 직후 프레임 3까지 보여 주고 반동 최고점 전에 끊긴다.
  - 쌍권총: 오른쪽 0초, 왼쪽 0.25초에 반동이 시작한다. 기획 단발값(오른쪽 0.05, 왼쪽 0.30초)과는 0.05초 차이다.
  - 풀오토 평균 사용: 가능하다. 앞 x는 0.510~0.516(±0.6px)으로 거의 고정이다. 높이는 1.6초 중간의 주춤(약 0.54~1.4초)에서 0.02(4px) 내려간다. 평균 (0.513, 0.739)을 쓰면 오차가 최대 0.016(3px)이다. 정확히 맞추려면 현재 프레임의 JSON 값을 쓴다.
