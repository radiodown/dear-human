# 22. 총기별 탄창·재장전·파츠 모션

[문서 목록](../README.md) · 총기 설정에 따른 재장전과 장전 모션은 사용자 요구사항이다. 아래는 목표 설계다. 현재 rig_002 샘플에서 탄수·일반/빈 장전·손 목표·분리 탄창의 첫 초안을 구현했으며 [24](24-motion-rig-test.md)를 따른다. 실제 게임 연결·손 모양/조작부 보정·소리·전체 R 검수는 후속이다.

## 1. 초기 범위와 기본값

초기 M16도 탄창을 소비하며 재장전한다. 이전의 ‘재장전 없음’ 계획을 대체한다. 총기별 탄창 용량·예비탄 정책·일반/빈 탄창 장전 프로필·이동 배율·자동 장전 여부를 데이터로 관리한다. 수치 원본과 JSON은 [07](07-data-and-assets.md)에 둔다.

| 설정 | M16 제안 기본값 | 의미 |
|---|---|---|
| 탄창 용량·시작 탄수 | 30발·30발 | 실제 발사 성공마다 1발 소비 |
| 예비탄 | 무제한 | 재장전은 필요하며 탄약 획득·보급은 후속 |
| 일반 장전 | 2.2초 | 탄창에 1발 이상 남았을 때 |
| 빈 탄창 장전 | 2.8초 | 0발일 때, 추가 조작 큐 포함 |
| 수동 입력 | `R` | 탄창이 덜 찼고 예비탄이 있으면 시작 |
| 자동 장전 | 켜짐 | 0발 상태에서 발사 시도 시 시작 |
| 장전 중 이동 배율 | 0.75 | 공통 하체 걷기는 계속 재생 |
| 장전 중 사격·수동 취소 | 불가 | 발사 입력·R 연타가 장전 시간을 줄이지 않음 |

이는 실제 M16의 장전 속도를 주장하는 자료가 아니라 플레이 검증용 수치다. 장전 중에도 적·접촉 피해·스폰은 계속된다. 전투의 틈을 고르는 행동으로 만들되, 모션 검증 후 시간·이동 배율을 조정한다.

초기 탄수는 ‘지금 발사 가능한 총 탄수’로 추상화하고 별도 약실 탄수와 +1발을 시뮬레이션하지 않는다. 일부 남은 탄창은 재사용 가능한 탄약으로 계산해 버리지 않는다. 탄창 인벤토리·탄종·약실 조작·탄약 획득은 후속이다.

## 2. 동작과 상태

캐릭터의 하체 idle/walk와 별개로 무기 행동을 `READY / RELOADING / DISABLED`로 관리한다. 탄수 0은 READY에서도 가능한 값이다. 생존·PLAYING·무기 행동·발사 대기시간·탄수를 모두 통과한 발사만 탄수를 1 줄이고 shot_id·반동·화염·판정을 만든다. 빈 총·장전 중 발사에는 총알·명중·발사 통계가 생기지 않는다.

R과 발사가 같은 틱이면 유효한 수동 장전 요청을 먼저 처리한다. 만탄·예비탄 0으로 장전이 불가능하면 사격은 기존 조건으로 평가한다. 장전 시작 때 남은 탄수로 일반/빈 프로필을 고정한다. 이미 RELOADING이면 R을 무시하고 타이머를 다시 시작하지 않는다. 0발 발사 시도는 설정에 따라 자동 장전을 시작한다. 방아쇠를 놓으면 장전 완료 후 자동으로 발사하지 않는다.

장전 타이머와 모션은 고정 틱의 동일한 경과 시간을 사용한다. 일반/빈 장전 모두 **해당 duration_sec 종료 때 탄약을 한 번 반영**한다. 그 틱은 완료 전환까지만 하고, 다음 틱부터 기존 발사 간격을 만족하면 사격을 허용한다. 장전이 발사 쿨다운·bloom을 강제로 초기화하지 않는다. bloom은 기존 전투 시간의 자연 회복 규칙을 따른다.

일반 피격은 몸 반응·머리·의복의 작은 가산 모션으로 합성하며 장전을 취소하거나 시간을 늘리지 않는다. 좌우 전환도 같은 장전 위상으로 이어간다. 사망은 미완료 장전을 취소하고 손·탄창 표시를 정리한다. 이미 완료된 탄수 변경을 되돌리지 않는다. 재시작은 새 run_id와 만탄 상태로 초기화한다.

PAUSED·탭 숨김은 타이머·장전 모션·소리 큐도 멈춘다. STORY에 진입하면 진행률을 보존해 정지하고, 스토리 표시 포즈와 전투 장전 포즈를 분리한다. 스토리 관람/스킵이 장전 시간을 진행시키지 않으며 전투 복귀 때 저장된 위상을 복원한다. CLEAR/FAILED·실제 무기 해제는 미완료 작업을 취소한다. 초기에는 전투 중 무기 교체를 구현하지 않는다.

## 3. 탄약 계산·중복 방지

총기 정의는 공유 가능한 불변 데이터이고, 탄수·예비탄·장전 상태는 무기 **인스턴스별** 상태다. 같은 총기 정의를 샘플과 게임에서 사용해도 탄수를 공유하지 않는다.

유한 예비탄의 완료 계산은 `loaded = min(capacity - rounds_before, reserve_before)`다. 탄창에는 loaded를 더하고 예비탄에서는 같은 양을 뺀다. 무제한 예비탄이면 부족한 양만 채우고 예비탄 숫자는 따로 계산하지 않는다. 예: 탄창 12/30, 예비탄 10이면 완료 후 22/30·예비탄 0이다. 시작 후 외부 탄약 변경은 초기판에서 허용하지 않는다.

각 작업은 `(run_id, weapon_instance_id, reload_id)`와 선택 프로필·시작 상태·경과 시간을 가진다. 완료/취소는 동일 작업에 한 번만 적용하고, 이전 실행·무기·작업의 늦은 콜백을 무시한다. 게임 상태가 탄약을 변경하며 애니메이션 이벤트는 변경하지 않는다. 재생 속도·프레임 생략·느린 미리보기·중복 이벤트로 탄약을 복제할 수 없어야 한다.

중도 취소가 필요한 사망/해제에서는 완료 전 탄수·예비탄을 유지한다. 총에 붙은 탄창 표시를 복구한다. 탄창 분리·삽입 큐는 표현이므로 중간에 실제 탄약을 추가하거나 소모하지 않는다. 나중에 한 발씩 넣는 무기는 각 삽입 완료의 개별 탄약 반영·사격 취소 규약을 추가해야 한다.

## 4. M16 파츠와 장전 모션

무기를 본체·탄창·필요한 조작부로 분리한다. 기본 본체 그림에 붙어 있는 탄창을 장전 중 이중 표시하지 않게 한다. M16의 분리 탄창·조작부는 무기 자산이며 캐릭터 전신에 굽지 않는다. [16](16-modular-character-and-weapons.md)의 장착점·좌표 규약을 사용한다.

| 구간 | 캐릭터와 무기의 표현 |
|---|---|
| 준비 | 주 손은 총을 지지, 무기를 낮추거나 기울임 |
| 탄창 분리 | 보조 손을 고정 앞손잡이 IK에서 떼어 탄창 접점으로 이동 |
| 새 탄창 접근·삽입 | 손·탄창 접점·무기 삽입 소켓을 맞추며 기존 탄창과 교체 |
| 빈 탄창 추가 조작 | 지정한 조작부로 손 이동·조작, 일반 장전에는 생략 |
| 복귀 | 보조 손을 앞손잡이에 복원하고 사격 자세로 블렌딩 |

기본 파츠 리그·하체 보행·몸통·머리를 재사용하고 장전용 상체 포즈·손 모양·목표 경로만 추가한다. 무기 자세를 먼저 평가하고, 장전 위상에 따라 보조 손 목표를 grip→탄창/조작부→grip으로 전환한 뒤 양팔 IK를 푼다. 무기 장착점을 손의 자식으로 옮기지 않는다.

탄창이 손에 붙어 움직이는 구간은 임시 시각 부착으로 처리한다. 손 목표는 장전 프로필에서 먼저 정하고 탄창이 그 손을 따라가므로 ‘손이 탄창을 추적하면서 탄창도 손을 추적하는’ 순환을 만들지 않는다. 소매·장갑·어깨 갑옷의 가림 순서와 팔꿈치 꺾임도 함께 검수한다. rigid 흉갑은 장전 중에도 바스트 변형을 받지 않는다.

타이밍 큐의 기본안은 일반 0.25초 탄창 분리→1.25초 삽입→2.2초 준비 완료, 빈 장전은 같은 분리/삽입→2.2초 추가 조작→2.8초 준비 완료다. 어깨·머리·머리카락·의복에는 작은 지연 반응을 허용하지만 발사 반동 이벤트는 만들지 않는다.

2dimg2motion은 필요할 때 장전 키포즈·타이밍 참고로만 사용한다. 자동으로 총기 파츠·손 경로·탄약 상태를 추출한다고 가정하지 않는다. Spine 또는 같은 계약의 TypeScript 리그에서 실제 키·IK·탄창 뷰를 연결한다. 같은 장전 계열이면 프로필과 접점만 조정하고, 다른 계열이면 필요한 상체 동작을 추가한다. 총기마다 캐릭터 전체를 다시 생성하지 않는다.

## 5. 총기별 확장 계약

`ammo`는 용량·시작 탄수·예비탄 정책, `reload`는 strategy·자동 장전·이동 배율·일반/빈 프로필 ID, 프로필은 길이·모션 ID·표현 큐·손 목표/부착 전환을 제공한다. 예시는 [07](07-data-and-assets.md)을 따른다.

초기 지원 strategy는 `detachable_magazine` 하나다. 후속 산탄총 등의 `per_round`는 한 발씩 탄수 반영·삽입 반복·사격에 의한 취소, 기타 방식은 해당 무기의 개방/삽입/폐쇄 절차를 별도 구현한다. strategy가 추가됐다는 데이터만으로 구현됐다고 표시하지 않는다. 미지원 값·누락 프로필은 명시적 검증 오류이며 M16 장전을 임의로 적용하지 않는다.

장전 길이는 양수 유한값, 용량은 양의 정수, 시작 탄수는 0~용량, 유한 예비탄은 0 이상의 정수로 검증한다. 무제한 예비탄은 `reserve_mode: unlimited`·`initial_reserve: null`로 표시한다. 큐의 시간은 0~duration_sec 범위이며 같은 프레임에 여러 큐를 지날 때 각각 한 번만 처리한다. 필수 탄창/조작부/손 목표·모션 참조를 로드 때 확인한다.

## 6. 피드백·통합 샘플·에이전트 작업

HUD에는 별도 무기 영역으로 현재 탄수/용량, 예비탄(무제한은 ∞), 장전 진행률을 표시한다. 스킬 슬롯을 탄약 표시로 바꾸지 않는다. 탄창 분리·삽입·추가 조작·준비 완료의 소리와 손의 멈춤으로 장전 감각을 만든다. 장전 동안 전역 히트스톱·카메라 흔들림·발사 화염을 추가하지 않는다. 빈 총 소리는 연타 제한을 두고 재생한다.

기존 [18](18-preview-library-and-reuse.md)의 캐릭터/M16 페이지에 일반·빈 탄창 장전, 이동·반전·피격·갑옷 조합을 추가한다. `#/samples/weapons/m16_basic?motion=reload_empty` 같은 경로로 같은 공통 런타임을 확인한다. 탄수·예비탄·장전 ID·경과 시간·큐·손 목표·탄창 접점을 함께 표시하고 전체 재생·느린 재생·단계 확인을 제공한다.

미리보기의 임의 시점 탐색은 격리된 상태를 재구성한다. 되감기·반복 재생이 본편 탄수를 변경하지 않는다. 시간/큐 수정은 해당 장전 프로필과 관련 무기·장비 조합만, 공통 장전 로직 수정은 모든 장전 샘플을 재검수한다. 기존 캐릭터·걷기·사격·다른 무기 결과를 보존한다.

실제 게임 구현 때 `reload_started / reload_completed / reload_cancelled / ammo_changed`를 기록한다. 최소 공통 키는 run_id·weapon_instance_id·weapon_id·reload_id이며, 탄약 변경에는 이전/이후 탄수·예비탄을 연결한다. 소리·표현 큐는 별도로 기록하고 탄약의 권위로 사용하지 않는다. [08](08-feasibility-and-qa.md)의 R 검수를 통과해야 완료다. 현행 [자동화 CLI](20-agent-automation.md)는 문서 링크·JSON 구문을 검사하며 장전 런타임 검사기는 아직 없다.
