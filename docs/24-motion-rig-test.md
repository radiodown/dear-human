# 24. 채택 외형의 파츠 모션 시험

[문서 목록](../README.md) · 기준 외형은 [02](02-world-and-art.md), 채택·정리 기록은 [23](23-character-appearance-review.md)이다. 이 문서는 실제 구현한 첫 시험과 남은 검수를 구분한다.

## 1. 현재 결과

사용자가 채택한 검은 장발·전술 갑옷·3D 렌더 질감으로 **분리 파츠와 자체 WebGL 리그의 첫 모션 샘플**을 만들었다. 원화 한 장을 통째로 흔드는 방식이 아니다. 16칸 캐릭터 아틀라스에서 각 파츠의 UV 영역을 읽고, 몸통·팔·다리·머리·망토를 따로 배치한다. M16 본체·탄창은 독립 이미지다.

채택한 전신 기준화는 그대로 보존했다. 이전 분홍 머리 제복과 중단된 시험의 원본·프롬프트·기록은 사용자 요청으로 삭제했다. 새 파츠는 생성 초안이며 원화의 얼굴·재질·비례를 완벽히 옮겼다는 판정은 아니다.

일시정지·1프레임·느린 재생, 64/128px 기준 비교, 반동/고개/머리카락/안쪽 천/망토 on/off, 뼈대·손잡이·총구·메시 표시, 분리 파츠 보기와 다른 길이의 진단 도형을 제공한다. 진단 도형은 두 번째 완성 무기가 아니다. 캔버스의 화면 맞춤 배율이 추가되므로 64/128 옵션은 논리 크기 비교이며 정확한 물리 화면 픽셀 검증은 별도다.

URL의 motion은 idle/walk/fire/walk_fire/reload/reload_empty, time은 최대 10초의 재현 시점, paused=1은 정지 상태다. debug=1, mesh=1, face=left, weapon=diagnostic도 시험 입력으로 쓴다. 실제 버튼을 클릭한 검수와 URL로 재현한 정지 장면 검수를 구분한다.

## 3. 실제 처리 구조

공통 코드는 [리그 시뮬레이션](../game/animation/rig-core.js), [무기별 데이터](../game/animation/weapon-profiles.js), [WebGL 표시기](../game/animation/webgl-character.js)다. [기존 앱의 시험 화면](../game/rig-lab.js)이 이 모듈을 사용하며 향후 게임 씬에서도 같은 모듈을 불러오는 구조다. 아직 Phaser·Spine 런타임으로 이식하거나 실제 게임 씬에서 재사용한 것은 아니다.

1. 보행 키포즈·몸통의 대기 호흡을 평가한다.
2. 무기 장착점·반동을 정하고 같은 변환에서 두 손잡이·총구·탄창 소켓을 계산한다.
3. 두 팔의 2본 IK를 손잡이 목표에 맞춘다. 무기가 손을 추적하는 순환을 만들지 않는다.
4. 장전 위상은 보조 손을 탄창/조작부 목표로 이동시키고 기본 파지로 복귀시킨다.
5. 머리·머리카락·안쪽 천·망토에 각기 다른 감쇠 스프링을 적용한다. 머리카락·망토는 뿌리를 고정한 국소 메시로 변형한다.
6. 최종 표시에서 좌우를 한 번 반전하고 동일 총구에 진단 화염·발사선을 표시한다.

시뮬레이션은 고정 120Hz이며 큰 프레임 간격은 한 번에 0.1초까지만 처리한다. 탭 숨김·모드 이탈 때 누른 사격 입력과 누적 시간을 해제한다. 흉갑은 rigid, 다리 장갑은 분절 파츠다. 안쪽 천 변형은 흉갑에 가려지므로 겉판에 바스트 모핑이 나타나지 않는 것이 의도한 동작이다.

M16은 30발, 0.1초 발사 간격, 일반 장전 2.2초·빈 탄창 2.8초다. 장전 중 발사를 막고 완료 때 한 번만 보충한다. 탄창은 별도 파츠이며 손·탄창 교체 동작은 초안이다. 실제 조작부 애니메이션·여러 손 모양·장전 소리는 후속이다.

## 6. 판단과 남은 작업

**분리 파츠·외부 무기·IK·국소 메시로 웹 샘플을 만드는 구조는 첫 시험에서 성립했다. 제작 도구의 최종 채택은 보류한다.** 이번에는 자체 JavaScript/WebGL만 사용했고 Spine 편집기·공식 런타임·2dimg2motion·PixelFX를 실제 시험하지 않았다. 따라서 Spine과의 제작 시간·품질·비용 비교가 완료됐다고 결론 내리지 않는다.

현재 파츠는 완전한 90도 측면보다 3/4에 가깝다. 앞/뒤 팔다리를 같은 그림과 명암으로 재사용했고 주 손/보조 손도 같은 주먹 파츠다. 생성된 팔에는 약한 굽힘·장갑 연결 형태가 남아 있어 최종 어깨·팔꿈치·손목 가림, 목·머리 연결, 원화 대비 비례와 얼굴 일치도를 보정해야 한다. 머리카락/망토의 메시 움직임은 확인했지만 극단 자세·모든 위상에서 경계가 깨끗하다는 판정은 아니다.

다음 판단은 실제 재생에서 보행 접지·장전 파지·반동 속도감·원화 일치도를 평가한 뒤 한다. 파츠 보정 비용이 크거나 편집 제어가 부족하면 같은 파츠를 입력으로 Spine에서 비교한다. 갑옷 교체 100회, 실제 피격 혈액/진액·치명타·폭발·소리, 전투 판정·스토리·1스테이지는 후속 범위다. 현재 삼각 화염·발사선은 PixelFX 결과가 아닌 진단 표시다.

## 7. 보행·반동·원화 비례 보정 03

사용자가 첫 결과의 괴이한 보행과 파츠 비율을 지적해 공통 리그를 수정했다. GIF는 일회성 요청이므로 이번 보정에서는 생성·갱신하지 않았다. 아래는 현재 웹 샘플의 변경이며 앞 절의 첫 캡처·초기 7개 검사는 과거 기록으로 구분한다.

- 앞·뒤 무릎이 반대로 꺾이던 부호를 고쳐 두 무릎 모두 진행 방향으로 굽힌다. 접지 구간은 루트 이동과 정확히 반대인 선형 발 경로, 유각 구간은 속도가 이어지는 곡선으로 분리했다. 뒤꿈치 접지·발끝 밀기·발목 회전을 계산하고 골반의 하강/통과/상승과 시작·정지 블렌드를 연결했다.
- 반동 스프링의 수치 적분이 고주파 충격을 첫 틱에서 반대로 뒤집던 오류를 감쇠 진동의 해석적 갱신으로 수정했다. 총은 뒤로 밀리고 총구는 소폭 위로 들린 뒤 초과 튐 없이 복원한다. 머리·머리카락·망토의 발사 충격은 줄였다.
- 채택 원화의 정수리·턱·칼라·어깨·벨트·골반·무릎·발목을 수동 대조해 약 7.9등신의 기준을 정했다. 머리/목·몸통 길이·허리·다리 비율과 장착 위치를 재조정했다. 측면의 원근 단축은 별도로 고려하며 측정은 의학적 인체 치수가 아닌 이미지상의 시각 기준이다.
- 캐릭터 파츠는 높이와 원본 UV 영역의 종횡비로 가로 크기를 산출한다. 팔·다리는 관절 피벗 간 거리로 배율을 정해 찌그러뜨리지 않는다. 망토·하의도 원본 비율을 유지한다. 손목과 손바닥 접점을 분리하고 손목 각도를 보정했다.

현재 공통 코드는 [보행](../game/animation/gait.js), [비례 기준](../game/animation/proportions.js), 기존 시뮬레이션·WebGL 표시기를 사용한다. 새 파츠 이미지는 생성하지 않았으며 채택 원화와 파츠 아틀라스의 해시는 유지했다. [보정 화면/측정 기록](../art/characters/clone_01/motion/rig_002/reviews/gait_003/review.json)에 범위를 기록한다.

현재 모션 검사는 14개다. 양 무릎 방향·발바닥의 지면 관통·보행 중 다리 도달 거리·접지 발의 월드 미끄러짐·정지 시 연속성·반동 첫 틱 방향/총구 상승/복원·원화 등신과 관절 기준·원본 종횡비·손바닥 접점 검사를 추가했다. 기존 파이프라인 검사 14개와 합해 28개가 통과했다. 수학적 통과와 최종 시각적 자연스러움은 구분하며, 같은 전경/후경 그림과 한 종류의 주먹을 재사용하는 원화 한계는 남아 있다.

보행 설계는 [Animation Mentor의 사람 보행 키포즈](https://www.animationmentor.com/blog/tutorial-animating-human-walk-cycle/), 리그 분리는 [Spineboy의 골반·발 IK](https://esotericsoftware.com/spine-examples-spineboy)를 참고했다. 이번에도 Spine 편집기·런타임을 사용한 결과는 아니다. 웹의 대기·접지·통과·사격 시점은 로컬 Chrome으로 정지 캡처해 비교하며 새 GIF를 검수 수단으로 추가하지 않는다.

## 8. 100STYLE BVH 모캡 비교 뷰어 (시험 브랜치 test/bvh-motion-import)

현재 보행이 어색하다는 사용자 피드백에 따라 [25](25-human-motion-research.md)에서 추천한 100STYLE Neutral의 `ID`, `FW`, `TR1` 세 클립을 [mocap_100style_001](../art/characters/clone_01/motion/mocap_100style_001/records/source.md)에 원본 그대로 보관했다. 같은 캐릭터 페이지에 **모캡 비교** 탭을 추가했다.

- 진입점: [모캡 비교 · 전진 보행](http://127.0.0.1:4173/#/samples/characters/clone_01?view=mocap&clip=FW). URL에는 `clip=ID|FW|TR1`, `frame=<번호>`, `paused=1`을 쓸 수 있다.
- 공통 코드: [BVH 읽기·순운동학](../game/animation/bvh.js)과 [뷰어](../game/mocap-lab.js). rig_002 카탈로그가 `rig-lab.js`의 해시를 고정하고 있어서 그 파일은 수정하지 않았다.
- 표시: 왼쪽 화면은 BVH 뼈대를 측면 또는 정면으로 투영한다. 진행 방향 정렬(골반 yaw의 ±0.5초 원형 평균), 제자리 카메라와 50cm 지면 눈금, Frame_Cuts 유효 구간, 높이·속도 기준의 접지 추정, 관절 이름을 켜고 끌 수 있다. 오른쪽 화면은 기존 rig_002의 절차 보행이며 BVH와 연결되지 않았다. 두 화면의 타이밍도 맞추지 않았다.
- 검사: 합성 BVH의 순운동학·회전 순서·오류 입력 테스트와 실제 세 클립의 해시·프레임 수·관절 구성 테스트 5개를 추가했다. Node 19개와 Python 14개 테스트, catalog-check가 통과했다. 헤드리스 Chrome으로 FW 1200 프레임과 ID 900 프레임의 정지 화면을 캡처해 확인했다. 실제 클릭 조작 검수는 하지 않았다.
- 남은 작업: rig_002 리타겟(측면 투영, 길이 보정, 발 고정 IK, 상체는 무기 IK 유지), Frame_Cuts가 0부터 세는지 1부터 세는지 확인, 접지 추정 검증, 사용자의 클립 품질 검수.

## 9. BVH → rig_002 리타겟 초안 (retarget_001)

모캡 비교 화면의 오른쪽 기본값을 **리타겟 리그**로 바꿨다. 이 리그는 왼쪽 BVH와 같은 프레임으로 움직인다. 기존 절차 보행은 선택 메뉴에서 다시 볼 수 있다. 진입점은 [모캡 비교](http://127.0.0.1:4173/#/samples/characters/clone_01?view=mocap&clip=FW)다.

- 코드: [mocap-retarget.js](../game/animation/mocap-retarget.js). `CharacterRig`를 상속한 `MocapRig`가 rig_002 렌더러에 같은 형식의 pose를 넘긴다. rig_002의 해시 파일은 수정하지 않았다.
- 하체: 배율은 다리 길이 기준 1.794px/cm다. 골반 높이는 BVH 값을 따르되, 발이 닿지 않으면 골반을 낮춘다. 몸통 기울기는 Hips→Neck 벡터로 정한다. 발 각도는 발목→볼 벡터의 pitch이고, 발등을 들면 뒤꿈치, 발끝을 내리면 볼을 피벗으로 쓴다. 다리는 기존 2본 IK로 푼다.
- 상체: 기존 무기 장착점, 손잡이, 양팔 IK 결과를 새 몸통 좌표로 강체 이동한다. 손잡이 오차는 0을 유지하고, 연사와 반동도 그대로 동작한다.
- 발 고정: 접지 구간에서 피벗의 월드 위치를 고정하고 최대 6cm까지만 보정한다. FW 디딤발 미끄러짐은 중앙값 7.6→0px/s, 상위 10% 46→8px/s로 줄었다.
- 검사: 리타겟 테스트 6개(세 클립의 도달·바닥 관통·골반 범위, 발 고정, 손잡이·pose 형식, 임의 프레임 결정성)를 추가했다. Node 25개가 통과했다. 측정값과 방법은 [retarget.json](../art/characters/clone_01/motion/retarget_001/records/retarget.json)에 기록했다.
- 한계: 측면 투영이라 옆걸음과 회전은 짧아 보인다. BVH 발이 리그 부츠보다 길다. 걷기 팔 흔들기, 골반 회전, 머리 흔들림은 쓰지 않는다. 게임 씬과 파츠 모션 테스트 탭에는 아직 연결하지 않았다. 사용자 검수 전이다.

## 10. glTF/GLB 모션 가져오기 (import_001)

모캡 비교 화면에 **BVH · GLB · glTF 열기**를 추가했다. 연 파일은 "사용자 파일" 클립으로 왼쪽 뼈대와 오른쪽 리타겟 리그에 함께 적용된다. 파일은 브라우저에서만 읽고, 프로젝트에 저장하거나 업로드하지 않는다.

- 코드: [gltf-motion.js](../game/animation/gltf-motion.js)(GLB 청크, accessor, LINEAR/STEP/CUBICSPLINE 샘플링, 60fps로 다시 샘플링), [skeleton.js](../game/animation/skeleton.js)(Mixamo·Blender·VRM 관절 이름을 표준 이름으로 대응, 손가락 제거, 발끝 끝점 보충), [motion-import.js](../game/animation/motion-import.js)(확장자별 진입점). BVH도 같은 경로를 거친다.
- 단위는 다리 길이로 m/cm/mm를 판별한다. Armature 같은 상위 노드의 scale과 rotation도 반영한다. 애니메이션이 여러 개면 선택 메뉴가 나온다. `.gltf`는 외부 `.bin`을 함께 선택해야 한다.
- 검사: 100STYLE FW를 Mixamo 이름, Armature scale 0.01(m 단위), 프레임별 quaternion을 쓴 GLB로 바꿔 읽으면 BVH와 0.05cm 이내로 같은 위치가 나온다. 외부 .bin, 발끝 끝점이 없는 파일, 보간 방식, 오류 메시지 테스트를 포함해 5개를 추가했다. Node 테스트 30개가 통과했다. 데스크톱 브라우저 패널의 파일 입력으로 생성한 GLB를 열어 리타겟(IK 오차 0)까지 확인했다. 형식과 한계는 [formats.json](../art/characters/clone_01/motion/import_001/records/formats.json)에 기록했다.
- 한계: 실제 Mixamo 내보내기 같은 외부 GLB는 아직 시험하지 않았다. FBX는 Blender에서 GLB로 바꿔야 한다. sparse accessor는 지원하지 않는다. 채택할 원본은 mocap_100style_001처럼 `art/` 아래에 기록과 함께 보관해야 한다.
- 외부 GLB 시험(2026-11-06): 사용자가 받은 Quaternius **Universal Animation Library [Standard]**(CC0)의 `UAL1_Standard.glb`(제자리)와 `_RM.glb`(루트 이동)를 읽었다. 관절은 65개, 애니메이션은 43개다. Unreal 마네킹식 이름(`pelvis`, `thigh_l`, `calf_l`, `ball_leaf_l`, `neck_01`)을 대응표에 추가했고, Hips 위의 `root`는 제외한다. 제자리 클립은 디딤발이 뒤로 밀리는 속도로 진행량을 역산한다(Walk_Loop 92cm/s, 같은 동작의 루트 이동 97cm/s). Idle, Walk, Crouch, Jog, Sprint, Pistol_Idle에서 다리 IK 오차 0, 바닥 관통 없음, 디딤발 미끄러짐 중앙값 0이었다. 원본은 프로젝트에 복사하지 않았다. 측정값은 [formats.json](../art/characters/clone_01/motion/import_001/records/formats.json)에 기록했다. Node 테스트는 32개가 통과했다.
- 보관(2026-11-06): 사용자 요청으로 루트 이동 버전 `UAL1_Standard_RM.glb`(7.6MB)와 License, README만 [mocap_ual_001](../art/characters/clone_01/motion/mocap_ual_001/records/source.md)에 원본 그대로 보관했다. 제자리 버전과 FBX는 보관하지 않았다. 해시, 애니메이션 43개 목록, Walk_Loop 리타겟(IK 오차 0, 바닥 관통 없음) 테스트를 추가해 Node 테스트 33개가 통과했다. 모캡 뷰어의 기본 클립 버튼에는 아직 넣지 않았고, 파일 열기로 확인한다.

### 9.1 각도 기반 리타겟으로 수정 (2026-11-06)

사용자가 "뼈대와 리그가 다르게 움직인다"고 알려 와 원인을 측정했다. 발목 위치(상관 0.99)와 몸통(1.00)은 맞았지만 **무릎이 달랐다**(FW 굽힘 범위 BVH 0–64°, 리그 9–49°, 상관 0.65). 사람 다리의 허벅지:정강이는 약 1:1인데, 채택 원화에서 잰 리그는 66:90이다. 발목 위치만 맞추는 IK로는 무릎 각도가 달라진다.

- 수정: 모캡의 허벅지·정강이 측면 각도를 리그 마디에 FK로 그대로 적용한다. 바닥에 닿는 프레임 전후 6프레임만 바닥 IK와 각도를 섞는다. 발끝 차기 구간은 FK를 따른다. 평평하게 디딘 발이 있으면, FK 다리가 그 발에 닿도록 골반 높이를 맞춘다. 원화 비례는 바꾸지 않았다.
- 결과: FW 무릎 굽힘 범위가 0–64°로 같아졌다. 상관은 0.65→0.91, 평균 차이는 14°→5°, 정강이 상관은 0.99다. UAL Walk_Loop 무릎 상관은 0.97–0.98이다. 발 고정(FW 미끄러짐 중앙값 0), IK 오차 0, 바닥 관통 없음은 유지했다. Node 테스트 33개가 통과했다.
- 남은 차이: 발끝 차기 구간은 약 10° 덜 굽는다. 리그 정강이가 길어서 공중 발이 9px 정도 더 뒤로 간다. 팔은 계속 총을 쥔다.

### 9.2 시점 각도 조절 (2026-11-06)

채택 원화는 몸이 화면 쪽으로 돌아간 3/4 시점인데, 리타겟은 완전 측면(인물 오른쪽에서 본 모습)으로 투영하고 있었다. 모캡 비교 화면에 **시점 각도**(0° 측면 ~ 90° 정면, 프리셋 0/30/45/90°, URL `angle=`)를 추가했다. 왼쪽 뼈대와 오른쪽 리그가 같은 각도로 투영된다. 리타겟은 화면 가로축 R = 정면·cosθ + 왼쪽·sinθ으로 허벅지·정강이·발·몸통 각도를 다시 계산하고, 진행량은 cosθ만큼 줄인다. 0°는 이전 결과와 같다. 30·45·90°에서 IK 오차, 바닥 관통, 진행량 테스트가 통과했다(Node 34개). 원화에 맞는 기본 각도는 사용자가 정한다.
- 보정: 처음 구현에서는 리그 다리 시작점이 측면용 ±3px에 고정돼, 각도를 돌려도 오른쪽 모델의 다리가 벌어지지 않았다(30°에서 BVH 엉덩이 ±9px, 리그는 좌우 반대 ∓3px). 엉덩이 관절도 같은 시점으로 투영해 시작점을 `±3·cosθ + 투영 위치`로 바꿨다. 이제 30°에서 ±6.4px, 60°에서 ±14.8px다(BVH ±9, ±16.3). 상체 파츠와 어깨는 원화 한 장이라 각도에 따라 벌어지지 않는다.
- 재보정: 다리 뿌리를 투영 위치로 옮기자 허벅지 윗부분이 원화 골반에서 떨어져 사이가 벌어져 보였다(사용자 지적). 그래서 다리 뿌리는 rig_002 위치에 고정했다. 대신 엉덩이 관절의 좌우 성분 × sinθ만큼 옮긴 지점에서 모캡 각도로 펼친 발목을 구하고, 고정 뿌리에서 그 발목으로 IK로 뻗는다. 다리는 골반에 붙은 채 발 쪽에서 벌어진다. 0°는 각도 기반 결과와 같다(FW 무릎 상관 0.90–0.92).
- 골반 연결 보정: 몸통은 모캡 기울기(FW 최대 9°, TR1 17°, UAL 보행 평균 7.6°)만큼 엉덩이 관절을 중심으로 기우는데, 골반·치마 파츠는 0°로 서 있어 허리와 다리 시작점이 어긋났다(사용자 지적). 이제 골반 파츠도 같은 각도로 같은 중심에서 기운다. 다리 뿌리는 회전 중심에 있어 골반에 붙은 채 남는다. UAL은 정지 자세의 척추가 4° 앞으로 기울어 있고 캐릭터 자체도 대기 시 약 8° 기운다(정지 자세 기준을 뺀 값 4.3°). 기준 자세 보정 여부는 사용자 검토 후 정한다.

### 9.3 보행 떨림 수정 (2026-11-06)

사용자가 "걸을 때 부들부들 떨린다"고 알려 왔다. 프레임별 2차 차분(가속)을 재 보니 대부분 프레임은 매끄러웠지만(중앙값 0.1px) 특정 프레임에서 무릎·발목이 13–30px씩 튀었다. 원본 BVH 무릎은 0.7px였다. 원인과 조치:

- 발이 닿도록 골반을 낮추는 보정이, 발을 떼는 다리의 가중치가 0.01 아래로 내려가는 순간 통째로 꺼졌다. 골반이 3.5px 튀고, 거의 펴진 디딤 다리의 무릎이 8px 튀었다. → 다리별 IK 가중치에 비례해 적용한다.
- 거의 펴진 디딤 다리의 IK가 0.1px 차이에도 무릎을 크게 움직였다. → 남은 길이 3px 구간에 부드러운 IK를 적용했다(발이 최대 약 1.1px 덜 닿을 수 있다). 골반 높이는 미리 계산해 앞뒤 6프레임으로 다듬는다.
- 착지 직전 아직 쓸려 가는 발을 디딤으로 판정해 발 고정이 6cm 당겼다. → 디딤 판정에 피벗 속도 35cm/s 미만 조건을 추가했다.
- 시점을 돌리면 뒤꿈치↔발끝 피벗 전환 때 잘라 쓴 발 길이 때문에 위치가 튀었다. → 부호 있는 투영 길이를 쓰고, 두 피벗을 ±0.1rad 범위에서 섞는다.
- 발끝으로 차는 순간 가중치가 1에서 0.75로 떨어졌다. → 발끝 보정 시작을 발 고정 각도(20°)에 맞추고, 가중치·발 각도·몸통 기울기를 앞뒤 2프레임으로 다듬었다. FK↔IK 전환은 10프레임으로 늘렸다.
- 결과(FW 1000–1600): 무릎 최대 2차 차분 0°에서 12.9→2.6px, 90°에서 16.9→4.9px. 발목은 0°에서 14.1→2.6px, 90°에서 30.2→2.7px. UAL Walk 발 각도는 16.4→5.2°이고, 남은 꺾임은 30fps 원본 키프레임 때문이다. 떨림 회귀 테스트를 추가해 Node 테스트 35개가 통과했다.

### 9.4 뼈대 일치 모드 (2026-11-06)

90°처럼 원화와 다른 시점에서는 리그가 뼈대와 다르게 보였다. 시점을 돌려도 2D 원화는 돌아가지 않고, 기본 모드는 접지·비례를 우선하기 때문이다. 사용자가 "실제와 괴리가 있더라도 뼈대와 각도를 맞추고 싶다"고 요청해, 체크박스 **뼈대 일치(비례 무시)**를 추가했다(URL `match=1`).

- 다리: 투영한 엉덩이 관절 위치에서 시작해 허벅지·정강이 각도를 그대로 쓴다(FK). 바닥 IK와 발 고정은 쓰지 않는다. 가장 낮은 부츠 끝이 바닥에 닿도록 몸 전체만 위아래로 옮긴다.
- 팔: 모캡 위팔·아래팔 각도를 그대로 쓴다(오른팔 = 앞쪽 armA, 왼팔 = 뒤쪽 armB). 총은 기존 손잡이 위치를 유지한 채 앞손에 붙어 따라간다. 뒷손은 총에서 떨어질 수 있다.
- 한계: 발이 미끄러질 수 있다. 다리 뿌리가 골반 그림 밖으로 나갈 수 있다. 몸통·머리 그림은 돌아가지 않는다.
- 검사: 0·30·90°에서 다리·팔 각도가 모캡과 1e-6rad 이내로 같은지, 가장 낮은 발이 바닥에 닿는지, 총이 앞손에 붙어 있는지 테스트했다(Node 36개 통과).

### 9.5 상하 각도 (2026-11-06)

시점 각도 옆에 **상하** 슬라이더를 추가했다. 범위는 −60~+60°이고, +는 위에서 내려다보는 시점이다. 0 버튼으로 되돌리고, URL은 `pitch=`다. 화면 세로축을 높이·cosφ − (카메라 쪽 깊이)·sinφ로 계산한다. 왼쪽 뼈대와 오른쪽 리그의 다리·팔·몸통 화면 각도가 같은 시점을 따른다. 골반 높이·발 높이 같은 실제 높이는 바꾸지 않는다. 기본 모드와 뼈대 일치 모드 모두 적용되고, 0°는 이전과 같다. −45·+30·+60°에서 IK 오차, 바닥 관통, 뼈대 일치 각도 테스트가 통과했다(Node 37개). 원화 그림 자체는 돌아가지 않는다.

### 9.6 뼈대 비율 모드 (2026-11-06)

체크박스 **뼈대 비율**을 추가했다(URL `prop=1`). 허벅지:정강이, 위팔:아래팔 길이를 모캡 뼈대 비율로 바꾸고, 크기는 다리 전체 길이를 rig와 같게 하는 배율로 맞춘다. 100STYLE에서는 다리가 66/90 → 78.5/77.5px, 팔이 43/38 → 55.9/45.8px가 된다. 팔다리 파츠는 렌더러가 관절 사이 거리만큼 늘여 그리므로 그림 길이도 바뀐다. 몸통·골반·머리·부츠·손 크기는 바뀌지 않는다(rig_002 렌더러는 수정하지 않음). 기본 모드와 뼈대 일치 모드 모두에 쓸 수 있고, 기본 모드에서는 총 손잡이 IK를 새 팔 길이로 다시 풀어 오차 0px를 유지한다. 각도 기반 리타겟과 골반 높이 보정이 이미 비율 차이를 흡수하고 있어서, 무릎 각도 정확도는 거의 같다(평균 5.9°→5.8°). 이 모드는 보이는 비율을 맞추는 용도다. 마디 길이·접지·손잡이 테스트를 추가해 Node 테스트 38개가 통과했다.
- 그림 늘이기(같은 체크박스): 사용자 요청으로 **뼈대 비율**을 켜면 그림도 뼈대 길이에 맞춰 늘이거나 줄인다. 몸통은 엉덩이→목 길이 / 77px만큼 세로로 늘인다(100STYLE ×1.28, UAL ×1.40). 가슴·안쪽 천·골반 그림과 어깨·총 장착점이 함께 움직인다. 머리는 실제 머리 끝 관절이 있을 때 목→머리 끝 / 47px다(100STYLE ×1.00, UAL은 관절이 없어 그대로). 부츠는 발목→발끝 / rig 부츠 발목→발끝만큼 가로로 늘인다(×2.9). 접지와 바닥 관통 계산도 늘어난 부츠 기준이다. 손 그림은 그대로다. 그리기는 rig_002 렌더러를 상속한 [mocap-renderer.js](../game/animation/mocap-renderer.js)가 맡고, 원래 렌더러는 수정하지 않았다. 몸통·머리·부츠 배율 테스트를 추가해 Node 테스트 39개가 통과했다.

### 9.7 실시간 길이 (2026-11-06)

**뼈대 비율** 옆에 **실시간 길이**를 추가했다(URL `live=1`). 켜면 뼈대 비율도 자동으로 켜진다. 클립 고정 길이 대신, 현재 시점(좌우·상하)에서 그 프레임에 화면에 투영된 뼈대 길이를 쓴다. 대상은 허벅지·정강이·위팔·아래팔(좌우 각각), 몸통(엉덩이→목), 머리(목→머리 끝), 부츠(발목→발끝, 좌우 각각)다. 카메라 쪽을 향해 짧아 보이는 뼈도 그대로 짧아진다. 골반 높이는 이 길이로 미리 계산한다. 화면 확대 비율이 프레임마다 흔들리지 않도록 화면 맞춤은 클립 고정 비율로 한다. 기본 모드와 뼈대 일치 모드에서 마디 길이가 투영 길이와 같은지, 60° 시점에서 길이가 실제로 바뀌는지, 바닥 관통이 없는지 테스트했다(Node 40개 통과).

### 9.8 발끝 맞춤 (뼈대 일치 모드, 2026-11-06)

사용자가 발이 뼈대와 많이 다르다고 알려 왔다. 측정 결과 원인은 세 가지였다.

1. 원화 부츠는 발목→발끝이 15px이고, 같은 배율의 사람 발은 43px다. 원화 부츠의 발목 기준점은 바닥에서 19.5px 위이고, 사람 발목은 약 14px다. 발바닥이 둘 다 바닥에 붙어 있어도 발목→발끝 선이 평균 27° 달랐다.
2. 부츠 각도를 화면 투영 각도가 아닌 3D 발등 기울기로 계산했다. 60°에서 평균 10.5°, 상위 10%는 18.6° 어긋났다.
3. 2D 부츠는 카메라 쪽으로 돌릴 수 없다.

뼈대 일치 모드에서는 이제 화면에 투영된 뼈대의 발목→발끝 끝점 벡터에 리그 부츠 발끝이 오도록 부츠 회전과 가로 길이를 함께 푼다. 원화의 높은 발목은 부츠 기울기로 흡수한다. 결과(FW 1000–1600): 방향 차이는 모든 시점에서 0°다. 발끝 위치는 0°에서 0px(0/600 프레임 예외), 60°에서 평균 0.18px(27/600 프레임은 투영된 발이 발목 높이보다 짧아 방향만 맞춤), 90°에서 평균 1.35px(148/600)다. 비율 모드가 꺼져 있어도 뼈대 일치 모드에서는 부츠 길이만 이렇게 맞춘다. 기본 모드는 접지 우선이라 바꾸지 않았다. Node 테스트 41개가 통과했다.

### 9.9 몸통 디버그 선과 고개 따라가기 (2026-11-06)

리그 몸통은 rig_002에서 관절 없는 한 덩어리다. 가슴 갑옷은 rigid이고, 몸통은 엉덩이 관절 중심의 기울기 하나로만 움직인다. 머리는 스프링으로만 끄덕인다. 그래서 모캡의 척추 마디·목·머리 각도 중 상체 기울기만 쓰고 있었고, 디버그 표시도 팔다리만 그렸다.

- 디버그: **리그 뼈대·접지**를 켜면 엉덩이→목→머리 끝, 목→양 어깨 선도 그린다.
- 고개: 체크박스 **고개 따라가기**를 추가했다(기본 켜짐). 화면에 투영한 목→머리(끝) 방향이 몸통보다 얼마나 기울었는지에 따라, 머리와 머리카락을 목 아래 피벗 기준으로 돌린다. 반동·피격 스프링 끄덕임은 그대로 더해진다. 모캡 리그는 이제 항상 상속 렌더러로 그린다.
- 기준: BVH 정지 자세는 머리가 정확히 위를 향하지만, 사람은 앞을 볼 때 목이 약 21° 앞으로 나와 있어 대기 중에도 숙인 것처럼 계산됐다. 기준을 서 있는 프레임(골반이 최고 높이의 90% 이상, 상체 ±8.6° 이내)의 중앙값으로 바꿨다. 결과 범위: 100STYLE −12~+28°, UAL Idle·Walk ±0.2°, Hit_Head −12~+5°, Death01 −26~+2°. 서 있는 프레임이 없는 클립(웅크린 대기 등)은 전체 중앙값을 쓴다.
- 검사: 서 있는 동안 중앙값 0, ±0.7rad 제한, 끄기, 렌더러 경로를 테스트했다(Node 42개 통과). 몸통 선과 고개 회전은 크게 렌더링해 눈으로 확인했다.

### 9.10 척추 휘어짐과 어깨 위치 (뼈대 일치 모드, 2026-11-06)

- 척추: 화면에 투영한 척추 마디(Chest…, spine_01…)가 목→엉덩이 직선에서 앞뒤로 벗어난 거리를 5지점(목 0 ~ 엉덩이 1)에서 구한다. 이 값을 리그 몸통 길이 비율로 맞춰 가슴 갑옷과 안쪽 천 메시를 휜다. 디버그의 몸통 선도 같은 곡선으로 그린다. 최대 휨은 100STYLE 보행 4.2px, UAL 보행 1.9px, 사망 10.9px, 주먹 9.8px다. 가슴 갑옷은 rigid 파츠지만 이 모드에서만 휜다. 기본 모드는 휘지 않는다.
- 어깨: 모캡 어깨 관절의 목 기준 화면 위치를 몸통 길이 비율로 맞춰 리그 목점에 붙이고, 그 위치를 팔 시작점(어깨 패드 포함)으로 쓴다. 측면에서는 두 어깨가 목 아래 약 11px에서 거의 겹친다. 원화에 맞춘 rig_002 기본 위치(뒤 −12, 앞 +8)와는 다르다.
- 검사: 휨이 목·엉덩이 끝에서 0인지, 보행 휨 범위, 어깨 위치 공식, 기본 모드에서 휘지 않는지 테스트했다(Node 43개 통과). 주먹·사망 동작을 크게 렌더링해 확인했다.

### 9.11 뼈대 일치 모드의 몸통 각도 (2026-11-06)

사용자가 몸통이 뼈대와 완전히 다르다고 알려 왔다. 보행에서는 맞았지만, 큰 기울기에서 크게 달랐다. 수정 전 평균 차이는 UAL 웅크려 걷기 30°, 사망 38°, 구르기 40°(최대 158°)였다. 원인은 네 가지였다. 기본 모드용 몸통 기울기 제한 ±17°가 뼈대 일치 모드에도 걸려 있었다. 기준 자세의 척추 기울기(UAL 4°)를 빼고 있었다. ±180°를 넘는 회전을 이어 붙이지 않았다. 바닥 기준이 부츠뿐이라 구르기에서 몸이 바닥 아래로 들어갔다.

뼈대 일치 모드는 이제 화면에 투영한 엉덩이→목 각도를 그대로 쓴다. 제한과 기준 빼기가 없고, 회전은 이어 붙이며, 앞뒤 2프레임으로 다듬는다. 바닥 기준은 부츠·무릎·엉덩이·목·머리 끝 중 가장 낮은 점이다. 수정 후 평균 차이는 모든 클립에서 0.53–0.67°이고, 구르기 최대 3.3°다. 기본 모드는 총 자세를 위해 기존 제한을 유지한다. 큰 기울기 테스트를 추가해 Node 테스트 44개가 통과했다.
