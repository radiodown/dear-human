# 17. 파츠형 갑옷·전투복 외형

[문서 목록](../README.md) · 갑옷 외형의 부분 교체는 사용자 요구사항이다. 아래 슬롯·데이터·재질 구분은 설계안이며 아직 구현하지 않았다.

최신 외형은 [02](02-world-and-art.md)의 검은 장발·3D풍 전술 갑옷이다. 흉갑은 rigid로 고정하고 바스트 모핑을 겉판에 전달하지 않는다. 머리·망토·안쪽 천은 soft, 다리 장갑은 segmented로 구분한다. 사용자가 새 외형을 채택해 rig_002 파츠·자체 WebGL 모션 시험을 재개했다. 실제 범위와 결과는 [24](24-motion-rig-test.md)에 기록한다. 갑옷 교체·최종 보정·사용 도구 확정은 후속이다.

## 1. 기본 방향

무기뿐 아니라 **갑옷과 전투복의 겉모습도 부위별로 교체**하도록 준비한다. 같은 체형·공통 리그 안에서는 장비 그림과 부착·가림·움직임 설정을 추가하고, 캐릭터 전체 원화·공통 걷기를 다시 만들지 않는다.

이번에 다루는 것은 외형 구조다. 방어력·내구도·장비 등급·드롭·상점·인벤토리·장비 교체 UI는 현재 범위에 넣지 않는다. 이 외형 슬롯은 HUD의 스킬 슬롯과 별개의 데이터다.

세계관에서는 클론이 여러 공식 제복 중에서 자유롭게 선택한다. 제복의 다양성은 여러 의상을 시험하고 싶어 하는 괴짜 군수 담당관에게서 비롯되며, 서사 기준은 [15](15-worldbuilding.md), 초기 기본 복장은 [02](02-world-and-art.md)를 따른다. 사복 착용이나 추가 의상 자산의 제작 완료를 뜻하지 않는다.

여러 제복은 같은 인물의 공통 체형·리그 위에 의복 파츠와 재질 설정을 달리 적용하는 후속 외형으로 연결한다. 기본 제복은 [02](02-world-and-art.md)의 최신 사용자 채택안을 따르며 이전 노출 설정을 강제하지 않는다. 최신 외형은 빈 소매 코트가 아닌 어깨 망토이며 별도 파츠로 분리한다. 추가 제복 전체나 의상 선택 UI는 아직 구현하지 않는다.

## 2. 교체 단위

| 슬롯 ID | 외형 범위 | 분리 기준 |
|---|---|---|
| head | 모자·헬멧·머리 장식 | 얼굴·앞머리·뒷머리와 가림 관계 |
| torso | 재킷·조끼·흉갑 | 기본 몸통·가슴/의복과 겉판 구분 |
| shoulders | 앞·뒤 어깨 장갑 | 양 어깨의 부착점·팔 움직임 |
| arms | 상완·전완 장갑·장갑 낀 손 | 상완·하완·손 파츠별 연결 |
| legs | 스커트·골반 장갑·허벅지·정강이 장갑 | 관절을 가로지르는 판을 분절 |
| feet | 부츠·발 장갑 | 발 접지·바지/정강이와 경계 |

**외형 슬롯 하나가 PNG 한 장이라는 뜻은 아니다.** 몸통 세트에 앞판·뒷판·소매, 팔 세트에 상완·전완·손이 들어갈 수 있다. 장비 세트는 필요한 여러 attachment를 한 번에 장착한다.

첫 제복도 가능한 범위에서 이 구분에 맞춰 제작한다. 기본 제복·몸통 파츠를 보존하고 덮이는 부분만 표시에서 숨긴다. 장비를 제거하면 지정된 기본 복장이 복원된다.

## 3. 공통 리그와 외부 자산

갑옷은 캐릭터 기본 아틀라스와 별도의 자산 묶음으로 로드한다. AppearanceResolver가 슬롯·장비 정의를 읽고 RigAdapter의 부착점 별칭에 연결한다. 무기와 같은 방식으로 장비 추가가 캐릭터 전체 아틀라스 재패킹을 요구하지 않게 한다.

부착점 별칭의 예는 head_shell, torso_shell, shoulder_primary_shell, shoulder_support_shell, arm_primary_shell, arm_support_shell, leg_primary_shell, leg_support_shell, foot_primary_shell, foot_support_shell이다. 이름은 앱의 계약이며 Spine의 내장 이름이 아니다. 실제 뼈대·슬롯 매핑은 RigAdapter에서 정의한다.

몸통 갑옷은 기본 torso를 따르고, 어깨·팔·다리 장갑은 해당 관절 또는 장비용 보조 뼈대를 따른다. 한 장의 단단한 그림으로 팔꿈치·무릎 양쪽을 동시에 덮고 늘이지 않는다. 관절판을 나누거나 겹침을 둔다.

단단한 판은 외부 이미지 부착으로 시작할 수 있지만 새 천·유연한 장비에는 해당 파츠의 메시·가중치·리그 바인딩을 별도로 작성해야 한다. 이미지와 모드 이름만 바꾸면 메시와 물리가 자동 생성되는 것은 아니다. 이 작업도 캐릭터 전체 재생성과 구분해 장비 부위별 제작비로 기록한다.

## 4. 재질과 보조 모션

| 표시 모드 | 예시 | 움직임 |
|---|---|---|
| soft | 천·유연한 이너 | 해당 의복 메시의 작은 변형 허용 |
| rigid | 흉갑·단단한 어깨 판 | 부착 뼈대의 이동·회전만, 판 자체의 늘어남 금지 |
| segmented | 여러 판·관절 장갑 | 판은 강체처럼 유지하고 연결부·천만 제한적으로 변형 |

**단단한 흉갑을 입으면 겉판에 바스트 모핑을 그대로 전달하지 않는다.** 기본 프리셋은 rigid의 보이는 가슴 변형 전달량 0이다. 모션은 몸통 반동·판의 이동·아래쪽 천이나 틈의 작은 반응으로 표현한다. 기본 체형은 변경하지 않는다.

soft 의복은 기존 바스트/의복 모핑을 재사용하고, segmented는 유연한 부분에만 전달한다. 숨긴 파츠의 물리를 계속 계산할지 생략할지도 기록한다. 장비를 제거하면 기본 모션 설정을 복원하며, 앞선 장비의 제한값이 남지 않게 한다.

같은 표시 영역에 여러 장비의 전달 제한이 겹치면 가장 작은 허용 gain을 적용한다. 하나를 해제해도 남은 장비의 제한을 유지하고, 해당 제한 장비가 모두 없어져야 기본값으로 돌아간다.

## 5. 가림과 그리기 순서

- 헬멧은 지정한 앞머리·뒷머리 구역만 숨기고 제거 시 복원한다.
- 흉갑은 해당 제복/가슴 앞 구역을 가리되 목·겨드랑이·허리 뒤에 틈이 생기지 않게 한다.
- 어깨 장갑·팔 장갑은 팔 IK와 같이 움직이며 총·손을 가리는 순서를 검수한다.
- 장갑 낀 손은 손 외형과 손바닥 접점 보정을 묶어 적용한다. 손잡이의 정의는 무기가 소유한다.
- 앞·뒤 파츠는 좌우 전환 때 같은 리그 기준을 따르고, 그리기 순서를 손쉽게 문자열 정렬로 결정하지 않는다.

슬롯별 숨김 규칙은 장착 상태 전체에서 합성한다. 한 장비를 제거할 때 다른 장비가 여전히 가리는 영역까지 복원하지 않도록, 현재 장비들로부터 가림 상태를 다시 계산한다.

## 6. 무기 파지와 호환 범위

가벼운 제복·동일 체형의 표준 장갑은 공통 손·무기 장착·팔 IK를 재사용한다. 두꺼운 장갑은 손 파츠·손바닥 오프셋, 큰 어깨/흉갑은 clearance나 파지 보정을 추가할 수 있다.

보정은 무기 손잡이를 임의로 이동시키기보다 캐릭터·장비 fit profile과 무기군 hold_profile을 조합해 적용한다. 팔 길이를 늘려 문제를 숨기지 않는다. 보정 순서는 기본 리그 → 장비 fit → 무기군 파지 → 무기 장착·반동 → 양팔 IK → 보조 모션이다.

완전히 다른 체형, 거대한 외골격, 키·발바닥 높이가 바뀌는 장비는 표준 외형 교체 범위를 벗어날 수 있다. 이런 경우 별도 리그 호환 버전·장비 보조 뼈대·동작 보정이 필요함을 기록한다. 모든 외형이 작업 없이 호환된다고 약속하지 않는다.

## 7. 데이터 계약

외형 정의에는 appearance_id, slot_id, compatible_rig_ids, fit_profile_id와 파츠 목록을 둔다. 각 파츠는 외부 texture_key, anchor_alias, 표시 모드, draw_layer, 가릴 기본 영역을 갖는다. 조립에 필요한 피벗·배율·오프셋도 해당 장비 메타데이터에 기록한다.

모션 제한과 표시 가림은 장비 정의가 소유한다. 기본 캐릭터 프리셋을 덮어써 저장하지 않는다. 예제는 [07 데이터 규약](07-data-and-assets.md)에 둔다. 리그·슬롯·부착점이 호환되지 않으면 장착 전 오류로 확인한다.

초기 외형 교체는 collision_policy=cosmetic_only다. HP·피해·물리 몸체·Hurtbox는 그대로 두며 장갑이 커졌다고 피격 범위를 자동 확대하지 않는다. 향후 게임 규칙과 외형 사이의 차이를 검토할 때 별도 설계한다.

## 8. 초기 범위와 검증

기본 제복 한 세트를 제작 기준으로 삼고, Motion Lab에서 **검증용 몸통 판·어깨 판 도형**을 장착해 본다. 완성된 갑옷 여러 벌·장비 UI를 추가하는 것은 아니다.

1. 같은 캐릭터 원화·리그·보행을 유지하며 두 검증 부위를 교체한다.
2. 걷기·좌우 반전·연사·일반/빈 장전·피격에서 관절 틈·깨짐·총과의 간섭을 확인한다. [22](22-weapon-reloading.md)의 탄창 분리/삽입·보조 손 경로와 소매·장갑·어깨 판의 가림을 함께 검사한다.
3. soft와 rigid를 바꿔 보이는 바스트 모션 전달과 원복을 확인한다.
4. 무기 진단 도형과 갑옷 진단 도형을 함께 바꿔 손잡이·총구 오차 2px 이하를 목표로 검사한다.
5. 숨김·draw order·표시 모드를 100회 바꾼 뒤 기본 복장과 모션이 정상 복원되는지 확인한다.
6. HP·피해·Hurtbox 불변, 이전 외형 참조·텍스처 누적 없음, 호환되지 않는 장비의 오류 표시를 검사한다.

실제 검증은 아직 하지 않았다. 공통 리그·무기는 [16](16-modular-character-and-weapons.md), 보조 모션은 [13](13-secondary-motion.md), 실행 검수는 [08](08-feasibility-and-qa.md)을 따른다.
