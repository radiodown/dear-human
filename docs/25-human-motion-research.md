# 25. 인체 모션 데이터·연구 도입 조사

[문서 목록](../README.md) · 조사일 2026-11-06 · 대상: clone_01의 기존 2D 파츠 리그

## 1. 결론과 확인 범위

**실제 사람의 모션캡처 데이터를 우리 비례에 맞춰 변환하고, 발 접지·IK·전환 보정을 결합하는 방식을 권장한다. 첫 데이터 후보는 100STYLE의 Neutral 보행·대기·전환이다.** 지금처럼 사람이 움직이는 궤적을 코드에서 직접 정하는 부담을 줄일 수 있다. 최종 품질은 같은 캐릭터의 실제 재생 비교로 판정해야 한다.

공식 배포 페이지·연구자 글·논문 초록·공개 저장소·이용 조건과 현재 작업 폴더의 코드를 확인했다. 데이터 파일 다운로드, 논문 전체 재현, 라이브러리 설치, 모델 학습·추론, 모션 이식·브라우저 품질 검증은 이번 조사에서 수행하지 않았다. 아래 도입 순서와 검수 항목은 프로젝트에 대한 제안이다.

현재 구현·이전 검수 범위는 [24](24-motion-rig-test.md)를 함께 본다. 이번 조사에서는 기존 작업 중인 코드·이미지·측정 JSON을 수정하지 않았다. 외형과 M16, 2D 파츠 제작 방식은 유지하는 전제다. 아래 구현 설명은 조사 당시 로컬 작업본 기준이다. `gait.js`와 `proportions.js`는 당시 미추적 파일로, 이번 조사 문서 커밋에는 포함하지 않는다.

발 접지를 고려하지 않은 코드는 아니다. 현재도 지지 구간의 발 후진 속도와 이동 거리를 맞추고, 뒤꿈치·발끝을 기준으로 군화를 회전시킨다. 다만 보행 주기·골반·발 궤적은 수작업 값이고, 상체와 하체의 협응을 실제 측정 데이터와 비교한 상태는 아니다. 테스트 코드의 존재와 이번 조사에서 실행·통과한 검사는 구분한다.

`ik2`의 도달 거리 제한과 굽힘 방향만으로 모든 관절의 자연스러움이 결정되지는 않는다. 원본 자세를 따르는 무릎·팔꿈치 방향, 관절 한계, 지지발과 골반의 관계를 함께 다뤄야 한다. 현재 파츠의 3/4 시점·가림·손 모양 문제도 모션 데이터만으로 해결되지는 않는다.

100STYLE의 CC BY 조건은 저자·출처·라이선스 링크·변경 여부를 표시하는 방식으로 기록한다. 수정·상업 이용 허용 범위는 [Creative Commons 공식 설명](https://creativecommons.org/licenses/by/4.0/)을 따른다. 배포할 때는 해당 모션에 적용되는 고지를 제공한다.

다운로드는 필요한 파일부터 한다. [Zenodo 배포본](https://zenodo.org/records/8127870)은 원본 BVH 묶음 약 1.5GB, 가공 학습 데이터 묶음 약 14.8GB로 구분된다. 첫 재생 실험에 가공 학습 데이터 전체는 필요하지 않다. 개별 BVH 링크와 Frame_Cuts.csv는 저자 페이지에서 확인했다.

[100style-retarget](https://github.com/orangeduck/100style-retarget)은 변환된 BVH/FBX 참고 자료다. 모션 데이터와 동봉된 `Geno.fbx` 캐릭터의 이용 조건이 다르며, 후자는 비상업 연구용으로 명시돼 있다. 우리 캐릭터를 사용하고 동봉 모델을 게임 에셋에 포함시키지 않는다. 해당 변환본은 손가락 모션도 없다고 명시한다.

CMU 홈페이지 본문은 직접 열기에서 시간 초과가 발생했으나 공식 도메인의 검색 결과에 표시된 이용·노이즈 안내를 확인했다. 실제 파일을 취득할 때 해당 안내와 출처를 다시 보존한다. 이번 조사에서 개별 클립 품질이나 전체 데이터 무결성을 검사한 것은 아니다.

## 4. 함께 도입할 연구·구현

### 발 접지와 IK: 가장 먼저 적용할 후보

Daniel Holden의 [Inverse Kinematics and Foot Locking](https://theorangeduck.com/page/inverse-kinematics-foot-locking), 2026-07-30 글은 다리 IK, 접촉 시점 추출, 월드 좌표 발 고정, 고정/해제 전환, 오프라인 보정을 설명한다. [예제 코드](https://github.com/orangeduck/GenoView-InverseKinematics)의 [라이선스](https://github.com/orangeduck/GenoView-InverseKinematics/blob/main/LICENSE)는 MIT다.

우리 코드에는 발이 닿을 때 월드 접점을 보존하는 상태를 추가하고, 이동·장전 감속·정지 때도 그 목표를 따라가도록 다리 IK를 적용하는 방식이 적합하다. 뒤꿈치에서 발끝으로 접촉이 바뀌는 구간은 접점 전환으로 처리한다. 다리 최대 신전 근처를 부드럽게 제한하고 필요하면 골반 높이를 보정한다. 이는 현재의 수학적 접지 트랙을 실제 캡처·변속에서도 유지하기 위한 확장안이다.

### Inertialization: 자세와 속도가 끊기지 않는 전환

[Inertialization Transition Cost](https://theorangeduck.com/page/inertialization-transition-cost)는 관성화 전환에서 자세·속도 차이를 다루는 근거를 제공한다. 현재 보조 부위의 스프링과 달리, 전환 순간의 이전 출력과 새 클립 사이의 위치·속도 오차를 보존한 후 감쇠시키는 층을 두는 제안이다.

보행→대기, 대기→이동, 이동 중 장전 진입/복귀에 적용한다. 발 잠금 제약을 최종 단계에 다시 만족시키고, 각도를 보간할 때 ±π 경계에서 회전이 튀지 않도록 처리한다. 모든 관절을 강한 저역통과 필터로 지연시키면 입력 반응과 원본 동작이 흐려질 수 있으므로 전환 보정과 일반 재생을 구분한다.

### Motion Matching: 필요한 클립이 쌓인 다음

[Motion-Matching 예제](https://github.com/orangeduck/Motion-Matching)는 현재 자세·동작 특성과 목표 이동에 맞는 구간을 검색해 연결하는 공개 구현이다. 코드 MIT와 데이터 CC BY-NC-ND의 차이를 README가 명시한다. 기존 예제의 바이너리 데이터·학습 결과가 게임 상용 이용까지 허용된다고 간주하지 않는다.

우리 첫 단계는 소수 클립과 상태 전환으로 충분할 가능성이 높다. 시작·정지·후진·피격 등 조합이 늘어날 때 허용된 데이터만으로 검색용 특성을 만들고, 발 위치·속도·접촉·목표 속도로 검색하는 작은 시스템을 검토한다. C++/raylib 데모 전체를 JS 게임에 옮길 필요는 없으며 알고리즘만 공통 리그에 맞춰 적용할 수 있다. 신경망을 쓰는 Learned Motion Matching은 별도 후속 실험이다.

### 100STYLE의 원 연구: 나중에 스타일 다양화

[Real-Time Style Modelling of Human Locomotion via Feature-Wise Transformations and Local Motion Phases](https://arxiv.org/abs/2201.04439)는 스타일 조절과 관절별 위상을 활용하는 연구다. 보행 데이터만 가져오는 첫 실험과 이 신경망을 재현하는 작업은 구분한다. 첫 품질 비교 후 긴장·부상·피로 등 이동 변형이 필요해지면 검토한다.

### 영상 추출과 생성형 모델의 역할

[MediaPipe Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker?hl=en)는 이미지·영상에서 33개 몸 랜드마크와 이미지/3D 좌표를 출력한다. 직접 촬영한 참고 동작을 얻는 보조 경로가 될 수 있다. 이 좌표를 뼈대 회전·정확한 접지·소총 파지로 변환하는 처리는 별도로 필요하다. 단안 영상의 가림·깊이 추정 오차 때문에 정제된 모션캡처와 동등하다고 가정하지 않는다.

[MDM 공식 구현](https://github.com/GuyTevet/motion-diffusion-model)은 텍스트/행동 조건 생성과 모션 편집을 지원한다. [코드 라이선스](https://github.com/GuyTevet/motion-diffusion-model/blob/main/LICENSE)는 MIT지만 선택한 가중치·학습 데이터·SMPL 등 의존 자산의 권한은 따로 확인해야 한다. 모델의 출력 기능만으로 M16 탄창 접점·발 접지·우리 파츠 가림이 자동 해결된다고 볼 근거는 없다. 현재의 첫 개선안은 검수한 실제 동작 클립을 재생하는 방식이며, 생성 모델은 오프라인 초안 후보로 남긴다.

## 5. 우리 코드에 넣는 방법

다음은 아직 구현되지 않은 도입 설계다.

```text
출처·조건을 확인한 BVH / FBX
  → 오프라인 읽기·트리밍·축/단위/기준 자세 정규화
  → 원본 관절 계층의 전역 자세 계산
  → 우리 비례·게임 시점으로 재목표화
  → 골반/몸통/발 목표·회전·접촉·이동량 트랙 저장
  → 기존 고정 스텝에서 클립 평가·전환
  → 게임 이동과 발 접지·다리 IK 보정
  → 몸통 기준 무기 소켓·반동·장전 목표·양팔 IK
  → 머리카락/망토/안쪽 천 보조 모션
  → 기존 WebGL 파츠 표시
```

1. **뼈대는 동작의 기준으로 사용한다.** 원본 Hips/Chest/Head, 양측 Hip/Knee/Ankle/Toe, Shoulder/Elbow/Wrist를 의미로 대응시킨다. 여러 Chest 관절은 몸통 방향 계산에 활용할 수 있다. 원본 배우의 체형으로 채택 외형을 바꾸지 않는다.
2. **3D→2D 변환 후 다시 제약을 맞춘다.** 전진 방향을 화면 X, 높이를 화면 -Y로 정규화한다. 횡방향 성분을 버리면 팔다리 투영 길이가 줄어들 수 있으므로, 측면 보행을 우선 선택하고 현재 2D 길이에 맞춘 IK/최적화가 필요하다. 3D 좌표에서 Z만 삭제해 바로 파츠를 늘여 붙이지 않는다. 시점·축·회전 순서는 파일 헤더 기준으로 읽는다.
3. **이동량의 주인을 하나로 정한다.** 초기안은 게임의 횡이동 속도가 위치를 정하고 원본 이동량은 보폭·재생 위상의 기준으로 쓴다. 클립 루트 이동을 다시 더해 이중 이동하지 않는다. 역재생 보행으로 후진을 대체하지 않고 별도 후보를 검토한다.
4. **지지발은 현재 이동량에서 계산한다.** 클립에서 얻은 접촉 시점과 지면 높이·발 속도를 사용해 접촉을 확인하고 잠금/해제를 부드럽게 처리한다. 현재 `trackX`뿐 아니라 실제 뒤꿈치/발끝의 월드 좌표를 검사한다. 접점이 멀어져 다리가 닿지 않으면 골반·보폭 조정 또는 잠금 해제 규칙을 적용한다.
5. **상체 제약을 남긴다.** 일반 보행의 팔 흔들기를 총기 파지 위에 그대로 합산하지 않는다. 캡처에서 골반·가슴 움직임을 취하되 무기 변환→손잡이 소켓→양팔 IK 순서를 유지한다. 장전은 해당 탄창·조작부 이벤트와 손 모양을 별도 제작한다.
6. **게임 실행에는 가공된 트랙만 넣는다.** 전체 데이터와 연구용 Python/학습 환경을 브라우저에 넣을 필요는 없다. 원본 60fps 트랙을 시간 기준으로 보간하며 기존 120Hz 시뮬레이션과 연결한다. 원본 fps·재생 속도·접촉 이벤트를 명시해 속도를 두 배로 해석하지 않는다.

소스 파일·정확한 버전/해시·저자·라이선스·원본 fps·선택 프레임·축 변환·뼈 매핑·비례·변환 도구 버전·검수 결과를 실제 제작 시 `art/` 아래 대상별 새 버전 기록에 보관한다. 기존 rig_002와 채택 원화는 비교 기준으로 보존한다. 이 문서에서 새 에셋 버전이나 변환 CLI가 이미 존재한다고 가정하지 않는다.

## 6. 권장하는 첫 검증

**첫 목표는 Neutral 보행·대기·전환을 현재 캐릭터에 적용해, 수작업 보행보다 나은지 같은 페이지에서 비교하는 것이다.** 데이터 정리→뼈대 재생→파츠 적용을 나눠 실패 원인을 확인한다.

| 단계 | 확인 내용 | 판정 근거 |
|---|---|---|
| A. 소스 확인 | Neutral_FW/ID/TR1의 동작 구간·방향·T포즈 제거·루프 경계 | 원본 클립과 잘라 쓴 프레임 기록. 파일명의 의미만으로 품질 채택하지 않음 |
| B. 뼈대 비교 | 원본, 2D 변환 뼈대, 비례 보정 뼈대 | 골반·발·무릎 궤적, 발 디딤·체중 이동, 투영 오류 구분 |
| C. 파츠 적용 | 기존 수식 보행과 데이터 보행을 같은 속도/비례/크기로 재생 | 보행 리듬, 발 접지, 상체 협응, 관절 가림, 원화 일치 |
| D. 게임 제약 | 이동 사격·장전 감속·시작/정지·좌우·속도 변화 | 실제 접점의 월드 이동, 손잡이 오차, 관절 한계, 전환 순간 위치·속도 변화 |
| E. 통합 확인 | 30/60/120Hz, 탭 중단/복귀, 런타임 부하 | 기존 기능 회귀 여부·프레임 시간·메모리·실제 입력 재생 |

검수는 기존 [캐릭터 샘플](http://127.0.0.1:4173/#/samples/characters/clone_01?motion=walk)에서 누적한다. 새 사이트를 만들지 않는다. 원본 참고 영상·뼈대 데이터 재생·최종 파츠 재생을 구분하고, 현재 검수 결과를 새 버전의 통과 기록으로 옮겨 쓰지 않는다. 표의 수치 항목은 측정할 지표이며 이번 조사에서 측정한 결과가 아니다.

보행에서 개선이 확인된 뒤 달리기·후진·피격 후보를 늘리고, M16 이동 사격·장전의 상체 자세를 보정한다. Motion Matching과 생성형 모델 도입 여부는 그 다음에 결정한다. 뼈대는 자연스러운데 완성 화면만 어색하면 해당 파츠의 피벗·그림 시점·가림·손 모양 보정이 다음 작업이다.
