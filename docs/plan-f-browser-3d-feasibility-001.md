# 플랜 F 코드 생성 웹 게임 구현 분석

## 현재 구현

최신은 [005 C 앉기·이동 방향 시선](../art/characters/clone_01/motion/plan_f/procedural_005/README.md)이다. C키/버튼으로 앉기·서기를 전환하며 앉아 이동·사격할 수 있다. 캐릭터는 이동 방향을 바라보고 정지 시 마지막 방향을 유지한다. 동작·브라우저 검수 대기다.

이전 [004 카메라 시점 조절](../art/characters/clone_01/motion/plan_f/procedural_004/README.md)에서는 좌우·위아래 각도 슬라이더, 기본 시점 복귀, 일시정지 조절과 설정 저장을 추가했다. 브라우저 검수 대기다.

이전 [003 사격 자세·반동](../art/characters/clone_01/motion/plan_f/procedural_003/README.md)에서는 견착·양손 접점을 연결하고 총→상체→머리 반동·복귀와 단발/0.25× 검토 조작을 적용했다.

이전 [002 모델·재질·조명 개선](../art/characters/clone_01/motion/plan_f/procedural_002/README.md)에서는 Saltline 참조 클론을 조사해 곡면 형상·절차 PBR·환경 반사·깊이 음영·블룸과 격납고 배경을 적용했다. 이동·사격 범위와 외부 모델 없는 제작 원칙은 유지한다.

사용자 후속 요청으로 [클론01 이동·사격 001](../art/characters/clone_01/motion/plan_f/procedural_001/README.md)을 구현했다. 격투게임식 시점에서 코드 생성 인물·총의 이동과 연사만 지원한다. 아래의 몬스터·장전·피해·스테이지 계획은 아직 구현 범위가 아니다.

## 플랜 F의 목표

**Saltline처럼 캐릭터·무기·몬스터·배경·재질·모션·효과·소리를 JavaScript 코드에서 만들고 HTML·CSS·JS로 서비스한다.** 단일 index.html은 요구사항이 아니다. 우리는 역할별 파일·모듈로 나눠 기존 프로젝트 구조에 통합한다.

별도 GLB/FBX·외부 애니메이션 파일 제작·변환·로딩을 F의 기반으로 삼지 않는다. 기존 모델을 Base64나 정점 덤프로 JS에 포장하는 것도 목표에 해당하지 않는다. 형상 생성 규칙과 동작 계산 코드가 핵심이다. Three.js 같은 렌더링 라이브러리는 사용 가능하다.

기술적으로 구현 가능하며, 핵심 검토 대상은 코드만으로 원하는 인물과 모션 품질을 만들 수 있는가다. 기존 원화·설정은 디자인 참고다. FPS·횡스크롤 여부는 제작 원리와 별개이며 이번 결정으로 확정하지 않는다. 초기 문서의 GLB 재사용 우선안과 단일 HTML 선택 배포안은 이 기준으로 대체한다.

## 우리 게임에 적용할 방법

| 대상 | 코드 생성 방법 | 주요 난점 |
|---|---|---|
| 인물 | 신체 단면·곡선·비례로 메시 생성, 관절 계층·필요한 스키닝도 코드 구성 | 얼굴 미감·인물 구별·관절 변형 |

| 무기 | 총몸·총열·탄창 등을 치수·단면으로 생성하고 접점 함께 정의 | 디자인 특징·파지·견착 |

| 재질 | 셰이더·노이즈·Canvas·렌더 타깃으로 표면 패턴 생성 | 피부·머리 표현·초기 생성 시간 |

단순 도형 몇 개로만 표현을 제한할 필요는 없다. 생성 알고리즘이 정교하면 세밀한 곡면도 만들 수 있다. 다만 정밀함은 코드 작성과 시각 조정 비용으로 돌아온다. 코드 생성이 아트 제작 과정이나 모션 조정을 없애지는 않는다.

구조물·기계 무장·환경 효과·전투 로직은 참고 프로젝트와 가까운 문제다. 우리 인물의 얼굴·헤어·제복·전신 동작 품질은 별도로 입증해야 한다. Saltline 사례만으로 채택 원화 수준의 인물을 바로 재현할 수 있다고 보장하지 않는다. 조명과 후처리가 형상 오류를 해결하지는 않는다.

첫 시제품은 코드 생성 인물 한 명·무기 한 종류·토착 생물 한 종류·작은 전투 구역이다. 실루엣·얼굴·복장·보행·파지·사격을 먼저 평가하고 확대한다. 품질이 부족하면 생성 규칙과 표현을 조정한다. GLB 로딩으로 우회한 결과를 F 완성으로 처리하지 않는다.

## 기존 작업과의 관계

C는 기존 파츠의 Three.js 호환성, E는 별도 3D 제작 후 스프라이트 출력, 현재 GLB 탭은 준비된 모델·클립 재생이다. **F는 시각 자산과 모션 자체를 코드에서 만드는 제작 경로**다.

공통 샘플 셸과 로컬 Three.js r187, [웹 설계](04-technical-architecture.md)의 고정 틱·피해 이벤트·입력 계약은 재사용 후보다. GLTFLoader·GLB 재생기·외부 모션 파일은 F 의존성에 넣지 않는다. 기존 구현과 설계 문서를 구분하며 완성 전투 런타임이 이미 있다고 가정하지 않는다. A~E·GLB 실험·원본 자산은 보존한다.

## 모듈 구조 제안

아래는 전체 범위의 구조 제안이다. 현재 소규모 구현은 game/plan-f/의 index.js·model.js·model-build.js·weapon-pose.js·simulation.js·geometry.js·materials.js·environment.js·render.js·effects.js·styles.css를 사용한다. 개발과 서비스 모두 HTML·CSS·JS 모듈 구성이 기본이다. 단일 HTML 번들은 필수 산출물이 아니다.

## 구현 순서

1. **형상과 재질:** 코드 생성 인물·무기·생물을 공통 셸에 표시해 정지·회전·조명 변화에서 확인한다. 별도 모델·텍스처·스프라이트 파일 없이 생성한다.
2. **동작:** 코드 관절에 대기·걷기·사격·장전을 연결한다. 접지·파지·견착·반동·전환을 먼저 다루고 머리·옷자락 반응을 추가한다.
3. **전투 구역:** 코드 생성 지형에 입력·충돌·사격·장전·적 접근/공격·피격·사망·재시작을 연결한다. 카메라·조작 범위는 구현 시 별도로 정한다.
4. **플레이 흐름:** 선택한 조작·시점에 목표·스폰·출구·실패·정지를 연결한다. 횡스크롤이면 기존 세 구역→출구 규약을 참고하고, FPS면 자유 조준·카메라와 총구의 사선·3D 동선을 추가 설계한다.
5. **확대와 서비스:** 생성 규칙으로 인물·무기·적을 늘리고 효과·음향을 조정한다. HTML/CSS/JS와 필요한 라이브러리를 정적 웹으로 제공한다.

인간 지휘관은 근처 수송선에서 관제한다는 최신 설정을 유지한다. 클론 직접 조작을 원격 신체 조종 설정으로 확대하지 않는다. 제작 방식 결정만으로 세계관이나 전투 수치를 바꾸지 않는다.

## 시간과 성능

시뮬레이션은 고정 60Hz, 렌더는 브라우저 주기를 따른다. 탭 복귀 시 누적 시간을 제한하고 정지 중 장전·스폰·피해를 멈춘다. 모션은 게임 상태를 표시하며 발사·탄수·피해를 독립 판정하지 않는다. 총구 효과와 사격은 같은 최종 변환을 사용한다.

코드 생성은 모델 파일 전송과 변환 단계를 줄이지만 생성 후 메시·텍스처·그림자의 GPU 비용은 남는다. 기존 GLB 용량이나 Base64 크기를 F 성능의 근거로 사용하지 않는다.

- 메시·재질·오디오 버퍼는 초기화 때 생성·공유하고 매 프레임 전체를 다시 만들지 않는다.
- 정적 배경은 재질 공유·메시 병합·인스턴싱을 검토하고 관절 변형 비용은 별도로 측정한다.
- 효과를 풀링하고 그림자·후처리·DPR을 제한한다. 품질별 메시 분할 수·재질 해상도를 조절한다.
- 초기 생성·셰이더 컴파일과 플레이 프레임 시간을 구분한다. 작은 파일이 빠른 실행을 보장하지 않는다.
- 기존 CSP와 정적 JS 모듈 제공을 맞춘다. 외부 모델·텍스처·오디오 다운로드 없이 초기화부터 전투까지 실행되는지 확인한다.

초기 목표안은 데스크톱 1920×1080, DPR 1, 캐릭터 1명+적 10마리, 60fps다. 측정 전 목표이며 보장값이 아니다. GPU·브라우저·품질과 초기 생성 시간, 평균·p99 프레임 시간, draw calls·삼각형·텍스처 자원 수를 기록한다.

## 완료 조건과 현재 상태

코드 생성 형상과 동작으로 이동→사격→장전→적 처치→출구 또는 사망→재시작이 이어져야 한다. 벽 뒤 적에게 총알이 통하지 않고 한 발·한 사망이 중복 처리되지 않으며 정지·탭 숨김 후 입력과 시간이 복구되어야 한다. 외형·파지·접지·관통·성능은 짧은 실제 화면 검수로 확인한다.

별도 GLB/FBX·모션 파일·기존 스프라이트 로딩이나 기존 모델의 JS 인코딩은 F 완료 조건에 맞지 않는다. 시각·음향 생성 경로와 게임 코드가 프로젝트의 HTML/CSS/JS 구조에서 작동해야 한다.

현재는 클론01 이동·사격 001과 공통 탭을 구현하고 Chrome 조작·표시를 확인했다. 전체 전투·정밀 아트·성능 측정은 아직이다.
