# 01. 프로젝트 범위

[문서 목록](../README.md)

## 1. 프로젝트의 목적

**Dear Human**은 [15. 세계관](15-worldbuilding.md)의 근미래 성간 식민행성 베스퍼를 배경으로 한 2D 횡스크롤 액션 슈터다. 베스퍼는 같은 우리은하 안의 먼 대기행성이며 인간과 클론이 야외에서 호흡할 수 있다. 플레이어는 인간 지휘관이며, 전투에서는 배속된 여성 클론을 직접 조작해 전진한다. 초기 적은 미확인 군집생물의 근접 개체 1종이다. 장기적으로 여러 적과 스킬을 추가하되, 이번 제작은 기본 전투와 에셋 제작 방식의 가능성 검증에 집중한다. 성간항해 자체를 조작하는 시스템은 이번 구현 범위에 추가하지 않는다.

웹에서 실제 조작할 때의 모션 품질을 우선 검증한다. 확인할 질문은 다음과 같다.

1. 분리 원화와 공통 리그로 대기·이동·사격 자세를 만들고 2dimg2motion의 포즈 참고를 활용할 수 있는가?
2. 매 발 반동과 고개·머리카락·바스트의 지연·감쇠가 정지·이동 사격에서 읽히는가?
3. 총구·화염·판정이 변형된 캐릭터 자세에서도 일치하는가?
4. 실제 피격 때 플레이어 혈액과 적 진액이 위치·방향·성질로 구별되는가?
5. 웹 브라우저에서 이 모션과 적 20마리·입자·잔흔을 함께 처리할 수 있는가?
6. 군집생물이 몰려오는 짧은 스테이지를 끝까지 플레이할 수 있는가?
7. 캐릭터 파츠·리그·보행을 바꾸지 않고 다른 길이의 무기를 장착할 수 있는가?
8. 표준 체형의 갑옷 외형을 부위별로 바꾸고 관절·모핑·무기 파지를 유지할 수 있는가?
9. 일반·스침·치명타·폭발의 숫자·소리·잔해·사망이 구별되면서 연사 속도감이 유지되는가?
10. 컷신·미연시식 대화를 관람하거나 즉시 스킵해도 동일한 전투 시작·종료 상태에 도달하는가?

## 2. 필수 구현

| 구분 | 이번 구현 범위 | 완료 판단 |
|---|---|---|
| 스테이지 | 시작부터 출구까지 연결된 1개 | 전투 구간을 통과하여 클리어 가능 |
| 플레이어 | 조작 가능한 캐릭터 1명 | 좌우 이동, 방향 전환, 생존·사망 처리 |
| 무기 | M16 1종, 독립 이미지·장착·파지·총구 데이터 | 기본 사격·피해와 공통 리그 재사용 |
| 파츠 구조 | 분리 원화·공통 리그·양팔 IK·독립 무기 | 진단용 무기 도형 교체에도 캐릭터 자산 변경 없음 |
| 갑옷 외형 | 부위별 장착·가림·재질 모션 규약, 기본 제복과 몸통/어깨 진단 판 | 캐릭터 전체 재생성 없이 교체, 무기 파지·기본 복장 복원 정상 |
| 캐릭터 연출 | 기본 4동작과 일반/빈 탄창 장전, 매 발 반동, 고개·머리카락 흔들림, 바스트 모핑 | 손·탄창·총의 장전 접점과 독립 on/off·좌우 전환·총기 정렬 통과 |
| 재장전 | 총기별 탄창·장전 프로필, M16 수동/자동 장전, 탄약 HUD | 탄수 소비·사격 차단·완료 1회·탄창/손 모션 일치 |
| 피격 연출 | 혈액·진액·갑각 조각·몸 반동·재질음·일반/치명 강조 | 실제 피해와 등급에 대응, 무적 중 혈액 없음 |
| 전투 결과 | 명중도·스침·일반·크리티컬·약점, 대미지 숫자 | 탄도·피해·표시 일치, 중복 피해·치명 배율 없음 |
| 폭발·사망 | 샘플 범위 피해·폭발·잔해, 일반/치명/폭발 사망 프로필 | 거리·가림·대상별 1회 피해, 사망 후 즉시 판정 제외 |
| 이펙트 | 총구 화염, 탄도, 충돌, 낙하 액적·제한된 잔흔 | 실제 위치·방향과 일치하고 풀 상한 유지 |
| 웹 검증 장면 | 동일 게임 코드를 쓰는 Motion Lab | 모션별 비교·느린 재생·소켓·입자 디버그 가능 |
| 통합 샘플 | 한 사이트의 캐릭터·무기·외형·효과별 고정 페이지 | 첫 실제 산출물부터 등록, 기존 버전·모션 보존·재사용 |
| 적 | 일반 군집생물 1종의 다수 개체 | 접근, 접촉 공격, 피격·사망·제거 |
| 스킬 슬롯 | 여러 슬롯이 보이는 HUD | 기본 4개를 비활성 상태로 표시 |
| 스토리 | 도입·종료의 짧은 실시간 컷신·미연시식 대화, 상시 스킵 | 관람/스킵 결과 일치, 전투 입력 누출·중복 진행 없음 |
| 게임 흐름 | 시작, 플레이, 일시정지, 실패, 클리어, 재시작 | 재시작 시 스테이지 상태가 초기화됨 |
| 검증 도구 | FPS, 적 수, 발사·명중 수, 소켓 디버그 표시 | 가능성 판단의 증거를 남길 수 있음 |

플레이어는 처음부터 파츠형으로 제작한다. 플레이 가능한 무기는 M16 하나이며 Motion Lab의 다른 길이 무기 도형은 재사용 검증용 입력이다. 실제 두 번째 무기·상점·게임플레이 무기 전환을 구현한다는 뜻이 아니다. [16 파츠·무기 규약](16-modular-character-and-weapons.md)을 따른다.

갑옷 외형도 머리·몸통·어깨·팔·하체·발 슬롯을 염두에 둔다. 초기에는 기본 제복과 검증용 몸통·어깨 판만 확인하고 실제 여러 갑옷 세트·장비 UI·방어력·내구도는 구현하지 않는다. [17 외형 규약](17-modular-armor-appearance.md)을 따른다.

플레이어 1명은 **전투 화면에서 조작하는 클론의 수**를 뜻한다. 인간 지휘관은 서사적 플레이어이며 별도의 조작 병사를 추가하지 않는다. 군집생물은 별도 적 에셋이다. 적 애니메이션도 동일 제작 방식을 시험하되 클론의 M16 모션 검증을 먼저 한다.

군집생물은 게임 전체의 유일한 적이 아니라 최초 검증용 적이다. 이번에는 공통 적 식별자·피격 처리·스폰 데이터에 다른 종류를 연결할 수 있게 설계하고, 추가 적의 실제 행동·에셋은 후속 제작으로 둔다. 세력과 적 후보는 [11 적군과 세력](11-enemies-and-factions.md)을 따른다.

## 3. 스킬 슬롯의 경계

스킬은 이번 버전에서 직접 구현하지 않는다. 슬롯 UI와 슬롯 데이터 자리만 만든다.

- 4개 슬롯에 `1`, `2`, `3`, `4` 키 안내와 `미구현` 표시를 제공한다.
- 모든 슬롯은 `enabled=false`, `skill_id=null`이다.
- 키를 눌러도 공격, 이펙트, 마나 소비, 쿨다운이 발생하지 않는다.
- 아이콘은 빈 슬롯용 공통 그림만 사용한다. 실제 스킬 이름·성능은 정하지 않는다.
- 스킬 실행기, 스킬 클래스 계층, 가짜 시전 모션은 작성하지 않는다.

## 4. 이번 단계에서 제외

스토리는 [21](21-story-and-skipping.md)의 도입·종료 선형 장면을 포함한다. 분기 선택·호감도·백로그·음성·읽은 내용만 자동 스킵과 영구 읽음 저장은 후속이다. 이번 실행의 스토리 표시 끄기는 지원한다.

추가 스테이지, 군집생물 외 적의 실제 구현, 보스·특수 군집생물, 추가 플레이어, 실제 추가 무기·게임플레이 중 무기 전환·강화, 실제 스킬, 점프·사다리·복층 이동, 자유 각도 조준, 인벤토리, 성장·재화, 상점, 저장·로드, 멀티플레이, 모바일 조작은 제외한다.

탄약 수급은 후속이며 초기 예비탄은 무제한으로 제안한다. 탄창 소비·일반/빈 장전·손/무기 모션은 [22](22-weapon-reloading.md)에 따라 이번 범위에 포함한다. 기본 발사·장전·재질 피격·치명타·폭발음과 일반/치명/폭발 사망 반응도 초기 검증에 포함한다. 긴 시네마틱·전신 래그돌·사운드 폴리싱·전체 화면 유체 시뮬레이션은 후속이다. 실제 투척 무기 없이 통합 샘플에서 폭발 범위 피해와 연출을 검증한다. [19](19-combat-feel-and-damage.md)을 따른다.

## 5. 제안 실행 환경

| 항목 | 제안 |
|---|---|
| 플랫폼 | 데스크톱 웹 브라우저, 키보드·마우스 |
| 엔진·빌드 | Phaser 4.2.1, TypeScript, Vite 제안 |
| 버전 관리 | 착수 때 사용 버전·도구 커밋을 기록하고 검증 중 고정 |
| 화면 | 논리 해상도 640×360, 기본 창 1280×720 |
| 목표 프레임 | 렌더링 60 FPS, 판정 60Hz, 자체 보조 스프링 120Hz 기준·리그 도구의 실제 물리 주기 기록 |
| 스타일 | 단일 지면, 픽셀풍과 더 큰 인물 표시를 모션 가독성으로 비교 |
| 목표 플레이 시간 | 첫 클리어 2~4분. 테스트 후 조정 |

웹 구현은 사용자 지정이다. Phaser 구성과 캐릭터 크기·스타일은 조사 기반 제안이다. 첫 실험에서 64px와 128px 인물을 비교하며 최종 크기 변경은 스테이지·소켓·충돌 수치에도 반영한다. [12 도구 조사](12-web-tools-research.md)를 선택 근거로 삼는다.

## 6. 완료와 가능성 판정

원화·파츠·무기·모션·효과를 실제로 제작하면 파일 저장만으로 완료 처리하지 않는다. 공통 샘플 사이트의 해당 대상 페이지에 결과·버전·검수 상태를 등록하고 확인할 수 있어야 한다. 기존 결과 확인과 변경 범위 선택을 생성 전에 수행한다. [18 샘플 규약](18-preview-library-and-reuse.md)을 따른다.

프로토타입 완료는 필수 구현이 동작하고 [08 검증표](08-feasibility-and-qa.md)를 수행한 상태다. 기술 채택은 별도로 `진행 / 조건부 진행 / 보류`로 판정한다.

임시 도형으로 게임이 실행되는 것만으로 2dimg2motion·PixelFX 활용 가능성이 입증되지는 않는다. 최종 검증에는 실제 생성 캐릭터 모션과 PixelFX 산출물이 들어가야 한다. 대체 에셋을 사용하면 해당 항목은 미검증으로 남긴다.

리그가 움직이는 것만으로 무기 재사용·반동·머리 흔들림·바스트 모핑을 통과 처리하지 않는다. 모션별 on/off 영상과 혈액·진액의 실제 피해 이벤트 기록이 필요하다.
