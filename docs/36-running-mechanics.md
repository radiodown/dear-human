# 36. 달리기 접지·골반·다리 회수 보정

[문서 목록](../README.md) · [달리기](http://127.0.0.1:4173/#/samples/characters/clone_01?motion=run) · [뛰며쏴](http://127.0.0.1:4173/#/samples/characters/clone_01?motion=run_fire)

사용자의 원인 분석 후 코드 수정 요청에 따라 `running_mechanics_001`을 공통 리그에 연결했다. 기존 구현은 지지 중간에 골반이 높고 체공 때 낮았으며, 접지 이동 폭을 줄인 채 발 교대만 빨라졌다. 걷기와 같은 발 회수 곡선을 사용했고 보행 프로필 전환 중 접지한 발의 위치를 매번 다시 계산했다.

`game/animation/gait.js`의 달리기는 속도 260, 양발 한 주기 .90초, 지지 비율 .44, 최대 발 들림 42를 사용한다. 이전 값은 195 / .78초 / .46 / 18이다. 계산상 한 걸음 이동 거리는 약 76에서 117로, 접지 구간 이동 폭은 약 70에서 103으로 늘어난다. 이는 작성 수치의 변화이며 재생 측정이나 품질 통과 결과가 아니다.

전환 프로필은 접지 이동 폭·주기·지지 비율을 섞은 뒤 속도를 역산한다. 속도와 주기를 각각 선형 보간해 곱했을 때 중간 보폭이 양쪽 끝보다 커지는 현상을 피한다.

골반은 착지 후 지지 중간까지 압축되고, 발끝으로 밀어내며 올라간 뒤 짧은 체공을 거쳐 다음 착지로 내려온다. 지지 사인 곡선과 체공 포물선은 경계의 수직 속도를 공유한다. 달리기 발 회수는 뒤로 밀기 → 뒤꿈치 들기와 무릎 접기 → 앞으로 가져오기 → 착지 전 뒤로 당기기를 나눴다. 발목 목표와 부츠 각도로 같은 76+76 길이의 다리 IK를 움직이며 별도 무릎 그림이나 뼈 길이 확대는 사용하지 않는다.

`RunFootContacts`는 고정 시뮬레이션 스텝에서 접지한 발의 월드 track을 저장한다. 걷기↔달리기 전환 중 해당 발을 유지하고, 발을 떼면 남은 회수 구간에 걸쳐 다음 착지 위치로 연결한다. 감속 때문에 진행 중인 접지가 연장되지 않도록 현재 주기의 지지 종료를 제한한다. 정지·앉기 전환에서는 접지 보정을 줄여 기존 목표 자세로 넘긴다. 렌더러의 반복 호출은 접지 상태를 변경하지 않는다. 달리기를 사용하기 전의 걷기는 기존 발 경로를 사용한다.

같은 캐릭터 페이지의 달리기·뛰며쏴·Shift 이동이 이 계산을 공유한다. 013의 총 낮춤과 눈높이 조준 해제, 현재 작업 폴더에 있던 앉아쏴·손 파츠·천 제어를 유지했다. 새 이미지·프롬프트·GIF와 플랜 B/C 변경은 없다.

변경 전 두 소스는 [스냅샷](../art/characters/clone_01/motion/rig_005/records/runtime_snapshot_before_running_mechanics_001/index.json)에 보존했다. [레시피](../art/characters/clone_01/motion/rig_005/records/running_mechanics_001.json)와 [개발 인계](../art/characters/clone_01/motion/rig_005/records/development_handoff_running_mechanics_001.json)는 이번 작업 범위와 소스 해시를 기록한다. 과거 제출 프롬프트와 검사 기록은 수정하지 않았다.

사용자의 “검증은 내가할게 개발만해봐” 지시가 유효하므로 테스트·구문 검사·문서/목록 검사·브라우저 캡처는 실행하지 않았다. `untested`·사용자 검수 대기다. 전환 중 다리 도달 범위, 회수 실루엣, 착지 무게감, 뛰며쏴의 상체·총 흔들림은 실제 재생 검수가 남아 있다. 후속 결과는 새 `tests/running_mechanics_001`, `reviews/running_mechanics_001` 경로를 사용해야 하며 이번에는 검사 도구의 기본 출력 경로를 바꾸지 않았다.
