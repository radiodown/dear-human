# 플랜 D · 로컬 3D 기초 001

## 사용자 요청과 현재 범위

사용자는 붙여준 기술 설계서를 플랜 D로 지정하고 웹 대신 로컬에서 시도하겠다고 했다. 첫 개발 순서는 **1. 환경 구축 / 2. 간단한 뼈대 / 3. 렌더링 씌어보기**다. 후속 지시인 “이미지나 랜더링 피드백에 필요한건 검사는하되, 과도한 테스트는 하지말것”을 적용해 필요한 빌드·짧은 네이티브 실행·세 정지 이미지 확인만 수행했다.

기존 웹 플랜 A/B/C와 별도로 `native/plan-d/`에 C++ 프로젝트를 추가했다. 이번 네이티브 프로토타입은 웹 공통 미리보기의 제작·배포 대상이 아니며, 기존 웹 런타임과 채택 캐릭터·무기 원본은 수정하지 않았다. 사용자 제공 [설계서 원문](../art/characters/clone_01/motion/plan_d/preparation_001/source/technical-design-v0.2.md)은 제출 당시 내용으로 보존한다.

## 구현한 세 단계

| 단계 | 이번 산출물 |
|---|---|
| 환경 구축 | Apple Silicon macOS의 CMake 4.4.5 / Ninja 1.13.2 / SDL 3.4.20. C++20 빌드·로컬 실행 스크립트·SDL 버전 고정 |
| 간단한 뼈대 | 골반–허리–흉곽–목–머리와 양팔·양다리의 21개 관절. 부모–자식 계층, 좌우 구분, 정지와 간단한 보행 포즈 |
| 기본 렌더링 | 실제 3D 구/타원체/원기둥/상자, 바닥 격자, 정사영 카메라, 깊이 테스트, 기본 조명, 뼈대/도형/겹쳐 보기 |

각 관절의 월드 변환을 계산한 뒤 단단한 도형을 부착한다. CPU에서 이 작은 절차적 장면의 정점과 법선을 작성하고 GPU 버퍼로 올린다. 원본 PNG를 평면에 표시한 결과가 아니라 실제 3D 도형이지만, 정점 가중치 스키닝은 아직 없다. 단순 인체는 동작·렌더링 피드백을 위한 중립 마네킹이며 clone_01의 채택 외형을 대체하지 않는다.

X 이동 / Y 높이 / Z 깊이, 기본 전방 +X, Y-up을 사용한다. 카메라는 기본 수평 회전 25°·하향 12°이며 정측면 0°와 비교할 수 있다. RH 뷰 행렬과 SDL GPU의 0~1 깊이 범위에 맞춘 정사영을 사용한다. 게임 시간은 120Hz 고정 업데이트이며 표시와 분리한다. 보행은 관절 사인파와 최저 발끝 높이 보정만 있다. 발 접지 고정·충돌·체중 이동·완성 보행으로 보고하지 않는다.

## 그래픽과 의존성

공통 SDL GPU API가 macOS에서 Metal을 사용한다. [공식 GPU 안내](https://wiki.libsdl.org/SDL3/CategoryGPU), [셰이더 자원 바인딩](https://wiki.libsdl.org/SDL3/SDL_CreateGPUShader), [고정 SDL 릴리스](https://github.com/libsdl-org/SDL/releases/tag/release-3.4.20)를 확인했다.

macOS는 MSL 소스를 SDL로 실행 시 컴파일한다. Windows의 D3D12 / HLSL / DXC 빌드 분기는 작성했으나 실제 Windows 머신에서는 빌드·실행하지 않았다. 하나의 macOS 바이너리를 Windows 실행 파일로 보고하지 않는다. 이번 환경은 Homebrew의 SDL을 사용하며 다른 환경에서 정확한 SDL 버전을 찾지 못하면 CMake가 같은 고정 소스 릴리스를 받는다.

창과 PNG는 동일한 RGBA8 오프스크린 GPU 타깃을 사용한다. 창에는 이 타깃을 blit하고, 명시적 캡처 요청에는 GPU fence 완료 후 같은 타깃을 내려받아 PNG로 저장한다. 쓰기 전용 스왑체인을 읽거나 코드로 결과 이미지를 별도 합성하지 않는다.

## 실제 확인과 남은 범위

Apple Clang 21.0.0으로 첫 Debug 빌드가 오류·경고 없이 끝났다. Metal 디바이스·셰이더·깊이 타깃·창 표시·GPU PNG 저장을 세 번의 짧은 실행으로 확인했다. 각 실행은 실제 창에서 3프레임만 표시한 뒤 종료했다.

- [겹쳐 보기](../art/characters/clone_01/motion/plan_d/preparation_001/reviews/overlay.png): 중립 도형과 같은 계층의 관절이 정렬되어 표시된다. 가려진 관절을 보기 위해 뼈대는 깊이 테스트 없이 겹쳐 그린다.
- [뼈대 보기](../art/characters/clone_01/motion/plan_d/preparation_001/reviews/bones.png): 머리·척추·양팔·양다리 연결과 좌우 색 구분을 확인했다.
- [도형의 보행 정지 포즈](../art/characters/clone_01/motion/plan_d/preparation_001/reviews/solid-walk-pose.png): 위상 1.0rad에서 팔·다리 관절 변화와 도형의 앞뒤 가림을 확인했다. 연속 보행 품질 검수는 아니다.

캡처는 모두 2560×1600이며 확인용 원본을 그대로 보관했다. 보기/일시정지/카메라/이동 입력 코드는 구현했으나 위 캡처는 명령행 초기 상태를 사용했다. 키보드·마우스 전체 조작, 자연스러운 보행, 장시간 성능, Windows는 사용자 검수 또는 후속 범위로 남긴다. 웹 검사·브라우저 캡처·단위 테스트 묶음·전체 프로젝트 검사는 수행하지 않았다. 소스·산출물·실행 출력의 기록은 [preparation_001](../art/characters/clone_01/motion/plan_d/preparation_001/README.md)에 분리한다.

현재 캐릭터 외형·텍스처·머리카락·망토·의상 변형·M16·견착·사격·장전·앉아쏴는 미구현이다. 이번 세 단계만으로 Dear Human 전체의 네이티브/3D 전환이 끝났다고 판단하지 않는다.
