# 16. 파츠형 캐릭터와 교체형 무기

[문서 목록](../README.md) · 파츠 분리와 캐릭터 재사용은 사용자 요구사항이다. 아래 파츠명·리그·데이터 형식은 설계안이며 현재 구현하지 않았다.

## 1. 기본 결정

**전투 조작 클론은 처음부터 파츠형 뼈대·메시 리그로 제작한다.** 이 문서의 플레이어 리그는 [15](15-worldbuilding.md)의 배속 클론을 가리킨다. 머리·몸·가슴/의복·팔·손·다리를 재사용하고 무기 이미지는 외부 자산으로 분리한다. 총을 그려 넣은 전신 시트를 플레이어의 최종 런타임 에셋으로 사용하지 않는다.

무기를 추가할 때 바꾸는 것은 무기 그림·장착 데이터·손잡이 위치·총구·반동·필요한 무기군 자세다. 캐릭터 원화 전체나 모든 걷기 프레임을 다시 생성하지 않는다.

추천 제작 경로는 **Spine Professional + 공식 Phaser 4 런타임**이다. 도구 선택은 권장안이며 구매·설치는 하지 않았다. 유료 도구를 쓰지 않는 경우에도 동일한 파츠·뼈대·소켓 규약을 지키는 TypeScript 리그를 작성한다. 단일 전신 이미지의 국소 변형으로 돌아가는 것은 이 요구를 충족하지 않는다.

## 2. 제작 도구의 역할

| 도구 | 역할 |
|---|---|
| Krita 또는 동등한 레이어 편집기 | 분리 원화·관절 겹침·가려진 영역 보완 |
| 2dimg2motion | 걷기·사격 자세의 키포즈·타이밍 참고, 적 프레임 제작 |
| Spine Professional | 공통 뼈대·파츠 메시·팔 IK·애니메이션·보조 물리 |
| Phaser + RigAdapter | 무기 외부 이미지 장착, 데이터→팔 목표·소켓·반동 연결 |
| PixelFX | 무기별 화염·충돌과 혈액/진액 원본 |

2dimg2motion의 전신 PNG가 자동으로 파츠·Spine 리그·IK 애니메이션으로 변환되는 것은 아니다. 생성 포즈를 보고 리그 키를 작성하고, 필요한 분리 원화는 별도 제작·보정한다. 이 준비 비용은 최초 캐릭터 제작비로 측정한다.

## 3. 최소 파츠

| 묶음 | 필요한 파츠 | 기준 |
|---|---|---|
| 머리 | 얼굴/머리 본체, 앞머리, 뒷머리 | 고개와 머리카락의 지연을 분리 |
| 몸통 | 기본 몸통·제복, 가슴/앞쪽 의복 메시, 필요 시 재킷 끝 | 바스트 변형이 어깨·총을 끌지 않음 |
| 팔 | 앞·뒤 각각 상완, 하완 | 두 뼈 IK로 자세 조절 |
| 손 | 주 손잡이용 손, 보조 손잡이용 손 | 필요 시 무기군별 손 모양만 추가 |
| 하체 | 골반·하의, 앞·뒤 허벅지·종아리·부츠 | 걷기 공통 재사용 |
| 무기 | M16 본체·분리 탄창·조작부 | 손·팔·몸·화염을 그림에 포함하지 않음 |

모든 파츠는 투명 여백·축척·접합부 겹침을 제공한다. 팔꿈치·어깨·목·허리 뒤의 가려진 그림을 채워 회전 시 빈 구멍이 보이지 않게 한다. 소매는 해당 팔 파츠와 함께 움직여야 한다.

주 손/보조 손은 역할 이름이다. 화면의 왼손·오른손 위치와 같은 뜻으로 쓰지 않는다. 캐릭터를 뒤집어도 역할과 총 파지 위치는 유지한다.

## 4. 리그와 의존 관계

```text
actor_root                  # 발 원점·월드 이동·최종 좌우 반전
└─ pelvis
   ├─ leg_front / leg_back
   └─ torso
      ├─ head → hair_front / hair_back
      ├─ bust_cloth          # 가슴·의복 메시만 변형
      ├─ shoulder_primary → upper_arm → forearm → hand
      ├─ shoulder_support → upper_arm → forearm → hand
      └─ weapon_mount       # 팔의 자식이 아닌 안정된 장착 기준
         └─ recoil_pivot
            ├─ weapon_view  # 외부 이미지·자체 피벗
            ├─ primary_grip_target
            ├─ support_grip_target
            └─ muzzle / eject sockets
```

무기 자세를 먼저 결정하고 그 손잡이로 두 팔을 맞춘다. `손 → 무기 → 같은 손의 IK 목표` 같은 순환 의존성을 만들지 않는다. 장착점은 기본 몸통의 자식이고, 바스트/의복 보조 뼈대의 자식으로 두지 않는다. 갑옷도 이 장착점의 부모가 되지 않는다. 두꺼운 흉갑·어깨·장갑의 간섭은 장비 fit 보정과 무기군 파지에서 처리한다.

Spine 공식 문서는 슬롯의 무기 attachment 교체와 draw order를 설명한다. 이 프로젝트는 새 무기마다 캐릭터 아틀라스를 다시 묶지 않도록 **무기 그림은 외부 Phaser 뷰로 로드해 무기 슬롯에 연결하는 경로**를 우선한다. [Spine 슬롯](https://esotericsoftware.com/spine-slots), [Phaser 슬롯 객체 연결](https://esotericsoftware.com/spine-phaser).

위 트리는 논리 규약이다. 실제 Spine 뼈대명과 슬롯·Phaser 객체 사이의 변환은 RigAdapter 한 곳에 매핑한다. attachment의 피벗과 Phaser origin을 중복 적용하지 않는다.

## 5. 조립·사격 처리 순서

1. 공통 하체 걷기·몸통 자세를 평가한다.
2. 무기군 hold_profile과 캐릭터별 자세 보정으로 weapon_mount를 정한다.
3. 이번 발의 반동을 recoil_pivot에 적용한다.
4. 사격 자세에서는 무기 정의의 두 손잡이를 캐릭터 로컬 공간의 IK 목표로 변환한다. 장전에서는 프로필의 위상별 손 목표·탄창/조작부 접점을 사용한다.
5. 각 팔의 2본 IK를 풀고 손바닥 접점·손목 방향을 맞춘다.
6. 고개·머리카락·바스트 보조 모션을 적용한다. 팔·총의 장착 기준은 보존한다.
7. 최종 좌우·월드 변환 후 총구와 배출구를 계산한다.
8. 저장한 총구에서 판정·화염·탄도·탄피를 처리한다.

리그와 런타임의 자동 업데이트가 이 순서를 중복 실행하지 않게 한다. Spine의 constraint order와 앱의 목표값 주입 시점은 Motion Lab에서 검증한다. 기본 동작·발사 반동·보조 모션을 별도 경로에서 두 번 가산하지 않는다.

## 6. 팔 IK와 손 접점

Spine의 IK는 손·발 목표에 맞춰 뼈대 각도를 조정하며 1~2개 뼈 제약을 지원한다. 이를 양쪽 상완·하완에 사용한다. [공식 IK 문서](https://esotericsoftware.com/spine-ik-constraints).

손잡이 목표가 손바닥 접점이므로 손 파츠의 피벗·손바닥 오프셋도 데이터로 둔다. 손목 위치를 그대로 총 손잡이에 붙여 손바닥이 뜨는 오류를 막는다. 주 손목 회전은 무기 손잡이의 기준 각도, 보조 손은 앞부분을 잡는 기준 각도를 따른다.

목표가 팔 길이 밖이면 팔을 무제한 늘리지 않는다. 허용 범위로 제한하고 디버그 표시·검증 실패를 남긴다. 해결은 무기 스케일·장착점·hold_profile 보정이다. 팔꿈치 굽힘 방향은 좌우 반전과 전환에서도 안정적으로 유지한다.

## 7. 무기 자산·정의의 필수 값

| 항목 | 역할 |
|---|---|
| weapon_id / weapon_class | 개체 종류와 공통 파지·동작 분류 |
| texture_key / image_size_px | 외부 무기 그림과 원본 크기 |
| pivot_px / pixels_to_world | 이미지 장착 기준·월드 크기 변환 |
| primary_grip / support_grip | 원본 이미지에서의 두 손바닥 접점·각도 |
| muzzle / ejection | 총구·탄피 배출구의 원본 좌표·방향 |
| hold_profile_id | 무기군 공통 장착·어깨·손·팔꿈치 자세 |
| recoil_profile | 반동 길이·각도·복원·상체 전달량 |
| fire_interval / damage / range | 발사 판정 수치 |
| accuracy / critical / feedback profiles | 무기별 산포·연사 bloom·치명타·피격 강도와 소리 선택 |
| muzzle_fx / tracer_fx | 출력 효과 선택 |
| ammo / reload | 총기별 탄창·예비탄 정책·장전 방식·일반/빈 프로필·이동 배율 |
| visual.parts / reload sockets | 분리 탄창·조작부와 삽입·손 목표용 접점 |

부착점은 무기의 원본 좌표에서 정의한다. 매 캐릭터 모션 프레임마다 다시 총구 좌표를 찍지 않는다. 정확한 JSON 예시는 [07](07-data-and-assets.md)에 둔다.

명중도·치명타·폭발·사망 마무리는 [19](19-combat-feel-and-damage.md)의 공통 전투 결과를 사용한다. 무기별 판정값·반동·효과를 바꾸되 공통 캐릭터 파츠와 걷기는 재사용한다.

## 8. 총구 좌표 계산

원본 이미지의 점 p와 피벗 pivot에 대해 다음 변환을 같은 순서로 사용한다.

```text
world_point = actor_transform
            * mount_transform
            * recoil_transform
            * weapon_scale
            * (p - pivot)
```

손잡이 목표와 총구·배출구 모두 같은 체인을 사용한다. 카메라와 CSS/DPR 변환은 월드 판정 이후 화면 표시에만 사용한다. 왼쪽 전환도 최종 actor_transform에서 한 번만 처리한다.

## 9. 무기 추가 때의 실제 작업

**같은 양손 소총 계열:** 새 무기 PNG, 소켓·크기·반동·수치와 필요 시 작은 파지 보정을 추가한다. 캐릭터 파츠·뼈대·걷기는 재사용한다.

**권총·산탄총·중화기 등 다른 무기군:** 몸통·어깨의 hold_profile, 보조 손 사용 여부, 손 모양, 상체 발사·재장전 동작이 추가될 수 있다. 캐릭터 전체를 다시 생성할 필요는 없지만 자세 보정까지 항상 0작업인 것은 아니다.

재장전은 초기 M16부터 포함한다. 탄창·조작부는 **무기 자체 하위 파츠**로 분리하고, 장전 프로필에 따라 보조 손을 앞손잡이에서 탄창·조작부 목표로 전환한 뒤 복원한다. 상체 장전 동작과 손 모양을 추가하되 캐릭터 전신·공통 걷기를 재생성하지 않는다. 총기별 방식·시간·탄약 상태·취소·접점은 [22](22-weapon-reloading.md)을 따른다. 모든 무기를 M16과 같은 행동으로 처리한다고 가정하지 않는다.

## 10. 초기 구현 범위와 재사용 검증

플레이 가능한 무기는 M16 하나다. 상점·인벤토리·게임플레이 무기 전환·두 번째 완성 무기는 만들지 않는다. 대신 Motion Lab에서 다른 길이·손잡이 위치의 **진단용 무기 도형·데이터**를 임시 장착해 재사용 구조를 검증한다.

진단 도형은 출시용 두 번째 무기가 아니다. 캐릭터 원본·리그·걷기 파일을 바꾸지 않고 별도 텍스처·소켓 데이터만으로 장착되는지를 확인하는 테스트 입력이다. 같은 소총군 안의 도달 가능한 손잡이 범위로 만든다. 갑옷 외형은 별도 부위 슬롯으로 확장하며, 표준 체형의 장비와 무기를 함께 장착하는 검증은 [17](17-modular-armor-appearance.md)을 따른다.

장착 교체는 한 틱 경계에서 시각·소켓·수치·효과 프로필을 함께 갱신한다. 발사 대기시간을 0으로 돌려 연사 제한을 우회하지 않는다. 미완성 장착 중에는 발사하지 않는다. 이미 날아간 탄도·진액은 기존 월드 좌표를 유지한다.

## 11. 통과 기준

- M16과 진단용 무기 100회 교체 뒤 캐릭터 원화·리그·공통 보행 파일의 변경 없음.
- 주 손·보조 손과 손잡이 오차 2px 이하 목표, 총구·화염·발사선도 2px 이하.
- 좌우 반전·걷기·연사·피격·바스트 변형 중 손이 떨어지거나 총이 휘지 않음.
- 장착 불가능한 손잡이·누락 소켓은 명시적 오류로 확인하고 기본 M16로 조용히 대체하지 않음.
- 무기 외부 자산 추가가 캐릭터 전체 시트 재생성·캐릭터 아틀라스 재패킹을 요구하지 않음.
- 무기군이 바뀔 때 필요한 작업을 원화 전체·공통 보행·상체 자세·손 파츠·무기 자산별로 나눠 기록.

rig_002에서 자체 WebGL·분리 무기·양팔 IK의 첫 시험과 100회 무기 교체 시 파일 해시 보존을 확인했다. 이는 수학적 접점·정지 캡처 범위이며 실제 손바닥 그림의 파지·전체 애니메이션·장비 호환을 모두 통과한 것은 아니다. 실제 결과·남은 작업은 [24](24-motion-rig-test.md), 제작 흐름은 [05](05-character-motion.md), 전체 검수 기준은 [08](08-feasibility-and-qa.md), 보조 모션은 [13](13-secondary-motion.md)을 따른다.
