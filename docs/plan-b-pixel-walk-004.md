# 플랜 B · 도트 걷기 004

[문서 목록](../README.md) · [산출물](../art/characters/clone_01/motion/plan_b/pixel_walk_004/README.md) · [걷기 재생](http://127.0.0.1:4173/#/samples/characters/clone_01?plan=b&study=pixel_004&motion=walk)

사용자의 “캐릭터가 걷게 해줘” 요청으로 도트 003의 기준 외형을 사용한 **14프레임 제자리 걷기 초안**을 만들고 기존 캐릭터 페이지에서 자동 재생하도록 연결했다. 새 기본 선택은 ‘플랜 B · 도트 걷기’의 ‘도트 004 · 걷기’다. `./run.sh`로 예제 서버를 실행한다. 도트 003 정지 이미지와 001/002/003의 실패 기록, 플랜 A/C는 유지한다.

## 생성과 저장

키포즈의 확대를 줄이기 위해 이번에는 512×512 기준 이미지를 그대로 네 칸에 복사한 1024×1024 입력 보드를 만들었다. 내장 `image_gen`이 그 보드의 다리와 하단 망토를 편집하게 하고, 머리·흉갑·양팔·M16의 크기와 위치를 유지하도록 지시했다. 큰 보폭과 높은 무릎 들기를 줄였다. 기존 반려 키포즈는 생성 입력으로 사용하지 않았다.

02/05/08/11의 네 키포즈를 한 호출로 생성했다. [기준·키포즈 대조](../art/characters/clone_01/motion/plan_b/pixel_walk_004/reviews/key-size-comparison.png)에서 머리·흉갑·어깨~벨트·M16이 기준과 가까운 크기를 유지하는 것을 확인하고 중간 프레임 생성으로 진행했다. 이는 아트 채택이 아닌 다음 생성 단계의 시각적 승인이다.

01/03/04/06과 07/09/10/12의 중간 프레임은 각각 네 칸 시트로, 승인한 키포즈와 기준 이미지를 함께 참조해 두 호출로 생성했다. 전체 이미지 호출은 세 번이다. 정확한 영어 JSON/MD 프롬프트와 실제 도구 시간은 `records`에 저장한다. 모델 ID·seed·실제 과금은 도구가 노출하지 않아 null이다.

Python/Pillow는 기준/키포즈 복사로 입력 보드 구성, 전체 시트의 공통 배율 표준화, 동일 셀 분리, 거의 투명한 alpha≤8 잡음 정리, PNG 패킹과 비교판에만 사용했다. 포즈 생성·관절 변형·절차적 보간·개별 프레임 확대/축소·중심/발 높이 맞춤은 하지 않았다. 00/13은 도트 003 기준 PNG와 byte-identical이며, 네 키프레임은 대응하는 전체 프레임과 동일하다.

- [재생 manifest](../art/characters/clone_01/motion/plan_b/pixel_walk_004/output/manifest.json): 512×512 RGBA, 14프레임, 프레임당 75ms, 전체 루프 1.05초.
- [전체 프레임 대조](../art/characters/clone_01/motion/plan_b/pixel_walk_004/output/contact-sheet.png), `output/fullframe`의 14장, `output/keyframe`의 4장, PNG atlas.
- 원본 생성 시트와 편집 입력 보드, `recipe/pack.py`, [생성 기록](../art/characters/clone_01/motion/plan_b/pixel_walk_004/records/generation.json).

## 재생과 확인

같은 `FrameSequence`를 새 도트 보행과 이전 보행에서 공유한다. 서로 다른 manifest로 전환해도 첫 atlas만 계속 사용하던 문제를 고쳤고, 오래된 비동기 로드가 최신 선택을 덮어쓰지 않게 했다. 도트 atlas에는 이미지 평활화를 끄고 CSS pixelated 표시를 적용했다. 페이지 이탈·숨김에서는 재생이 멈춘다.

[짧은 Chrome 확인](../art/characters/clone_01/motion/plan_b/pixel_walk_004/reviews/browser.json)에서 자동 재생과 실제 canvas 픽셀 변화·일시정지·단일 프레임·02/05/08/11 이동·느린 재생·배경·이전 530px/새 512px atlas 전환·빠른 재선택·500px 표시·숨김 시 정지를 확인했다. 페이지 오류는 없었다. 두 변경 JavaScript의 구문과 필요한 PNG 계약만 확인했고 전체 게임 테스트·다른 플랜 검수는 실행하지 않았다.

## 한계와 검수 상태

걷기 재생은 연결했으며 최종 모션·아트 채택은 사용자 검수 대기다. 생성된 보행은 머리/상체/총의 눈에 띄는 확대가 줄었지만, 발의 불투명 외곽 하단이 434~437로 약 3px 흔들리고 망토/윤곽선/다리 하이라이트의 세부 변화가 남는다. 기준 자세로 돌아오는 루프의 멈칫함과 지지 다리 구분의 자연스러움도 검토 대상이다. 이 차이를 숨기는 개별 프레임 정렬은 하지 않았다.

공식 검증기의 파일 수·RGBA·동일 캔버스·투명 모서리·00/13 동일성·키프레임 동일성 조건은 확인했다. 그러나 **공식의 모든 프레임 발 기준선 완전 일치와 GIF 요구는 통과하지 않았다.** [원시 검사 결과](../art/characters/clone_01/motion/plan_b/pixel_walk_004/reviews/structure.json)에 그대로 남긴다. GIF는 자동 생성하지 말라는 사용자 지시에 따라 만들지 않았으며 브라우저 PNG 재생을 사용한다. 전체 공식 납품 통과로 보고하지 않는다.

M16은 전신 PNG에 포함되며 무기 교체·실제 리그·천/모발 충돌은 지원하지 않는다. 고정 팔레트나 단일 논리 픽셀 격자로 정리한 최종 게임용 스프라이트도 아니다.
