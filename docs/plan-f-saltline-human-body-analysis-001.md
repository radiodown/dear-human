후속 사용자 구현 요청으로 [전신 디테일 001](../art/characters/clone_01/motion/plan_f/human_detail_001/README.md)을 추가했다. 연속 외피·코드 스키닝·손가락·얼굴/머리/제복을 적용했으며 몸의 분기 연결은 연속 장 표면 추출로 구체화했다. 아래 내용은 작성 당시의 분석 기준으로 보존하며, 구현 범위와 미구현 항목은 후속 기록을 따른다. 새 외형은 검수 대기다.

사용자 요청: “플랜 F에도 적용할수있게 분석해서 md 파일로 남겨줘. 걔는 손만이지만 우리는 인체를 만들어야하니까”. 이 문서는 후속 구현자가 형상·리그·모션을 이어 만들기 위한 설계다. 새 캐릭터나 런타임을 제작한 기록은 아니다.

## 1. 적용 결론

**SALTLINE의 손에서 ‘인체 부위의 곡면 생성법’을, 로봇에서 ‘코드 생성 골격과 메시 연결 구조’를 참고하고, 사람의 전신 연결·연부 변형·얼굴·접지는 플랜 F에서 새로 설계한다.** 손을 크게 늘리거나 현재의 팔다리 도형에 표면 질감만 더하는 방식으로는 전신 인체 문제가 해결되지 않는다.

추천 구조는 **코드 생성 인체·제복의 연속 변형 메시 + 뼈에 고정되는 장갑판·장비 + 손/발 목표를 풀어내는 관절 제어**다. Three.js의 Bone·Skeleton·SkinnedMesh도 JavaScript에서 생성하므로 플랜 F 원칙에 맞는다. 외부 GLB/FBX·모션 로딩이나 기존 모델의 정점 덤프 포장은 필요하지 않다.

첫 개선 대상은 리안 한 명이다. 중립 자세에서 비례와 얼굴을 먼저 맞추고, 어깨·골반·팔꿈치·무릎을 굽혀도 표면이 이어지게 한 뒤 기존 이동·사격·장전을 연결한다. SALTLINE이 해결하지 않은 사람의 미감과 변형 품질은 별도로 확인해야 한다.

## 3. SALTLINE의 손은 어떻게 만들어졌는가

### 3.1 손바닥과 손가락은 단면을 쌓은 곡면이다

`EC`는 24개 점으로 된 단면들을 이어 손바닥을 만든다. 손등과 손바닥 쪽의 두께 함수를 다르게 쓰고, 손목에서 손가락 뿌리 쪽으로 폭과 끝 경계를 바꾼다. 구 하나를 납작하게 만든 것보다 손의 방향성과 볼륨을 직접 제어한다.

`C_`는 손가락별 길이·반경과 세 관절의 회전을 받아 `z_`로 보낸다. `z_`는 각 마디의 중심과 방향을 계산하고 관절 근처에 여러 단면을 둔다. 회전 보간, 관절 경계의 점 위치 제한, 마디 돌출과 패드, 끝부분 축소를 조합해 손가락을 만든다. 엄지는 `MC`에서 별도의 방향 배열을 쓰며 `SC`는 엄지와 손바닥 사이 연결 형상을 만든다.

**전신에 가져올 원리:** 팔·다리·몸통도 길이 방향 단면과 국소 돌출로 만들 수 있다. 다만 손가락은 한 줄 구조이고, 몸통은 목·양팔·양다리로 갈라진다. 손가락 생성기를 길게 늘리는 것만으로 겨드랑이나 사타구니의 연결 면은 생기지 않는다.

### 3.2 큰 형상과 재질 경계를 함께 설계한다

`Vv`는 손등 보호대, 봉제선, 손바닥 패드, 커프, 당김 탭, 소매를 별도로 만든 뒤 합친다. 소매에는 반경 변화와 각도·길이 방향 함수를 사용한 주름이 있다. 밝기·재질 구역은 정점 색에도 기록한다. `yl.collapse()`는 끝 링을 표시해 노멀을 평균 내는 처리이며, 일반적인 전신 토폴로지 자동 접합기로 해석하면 안 된다.

평면을 바라보는 방향에 따라 칠한 음영은 실제 조명의 대체물이 아니다. 전신에서는 회전하면서 이 음영이 어색해질 수 있으므로, 고정 방향의 강한 명암보다 봉제선·움푹한 곳·소재 구분을 나타내는 약한 마스크로 활용한다.

### 3.3 손의 모든 관절을 실시간 스키닝하는 구조는 아니다

`dm`은 정해진 파지 자세로 생성한 손과 소매를 배치한다. 오른손 검지만 두 지오메트리의 대응 정점 위치·노멀을 보간해 방아쇠 동작을 만든다. 왼손 장전은 손 그룹의 위치·쿼터니언을 시간별로 보간하고, 분리한 탄창을 손 변환에 연결한다.

이 방식은 제한된 손 동작에 효율적이다. 전신 전체에 같은 접근을 쓰면 자세마다 몸 메시를 준비해야 하고 어깨·골반 변형을 일반화하기 어렵다. **전신은 골격 스키닝을 기본으로 하고, 손 파지·관절 보정·눈 깜빡임 같은 제한된 변화에 동일 토폴로지의 형태 보간을 선택적으로 사용한다.**

### 3.4 1인칭 화면 전용 배치가 있다

손과 총의 루트를 카메라에 붙이고 별도 렌더 레이어를 사용한다. 이 경로의 메시 생성기는 그림자 투사를 끄며, 총구 위치를 계산할 때 월드 카메라와 viewCamera의 FOV 차이를 보정한다. 걷는 흔들림·조준·달리기·장전·스프링 반동이 카메라 앞 무기 자세에 합성된다.

플랜 F의 전신은 월드 안에서 발·몸·총이 같은 공간을 차지해야 한다. 카메라 자식 배치, 별도 FOV 보정, 화면에만 맞춘 손목 위치를 그대로 가져오면 견착·발사점·그림자가 어긋난다. 가져올 것은 **동작 채널의 분리와 부드러운 합성 원리**다.

## 4. 전신 리그에는 로봇 코드도 참고해야 한다

`iu`는 이름·부모·기준 위치로 뼈를 정의하고, 부품마다 연결할 뼈와 재질을 지정한다. 형상을 기준 자세 공간으로 옮긴 후 `skinIndex`와 `skinWeight`를 만들고, 재질별로 병합한다. `pm`이 Three.js Bone 계층과 Skeleton을 만들고 SkinnedMesh에 연결한다. 로봇 개에는 몸통·목·머리·다리·포탑, 드론에는 로터·짐벌 등 실제 움직이는 계층이 있다.

중요한 한계는 **각 정점의 첫 가중치만 1이고 나머지는 0**이라는 점이다. 로봇의 단단한 부품을 한 뼈에 고정하는 방법이지, 사람 피부를 두세 관절 사이에서 부드럽게 변형하는 구현은 아니다.

| 참고할 요소 | 전신 적용 | 새로 필요한 것 |
|---|---|---|
| 이름·부모·기준 위치를 가진 뼈 명세 | 신체 치수로 골격과 메시를 함께 생성 | 쇄골·척추 분절·전완 비틀림·발 관절 |
| 재질별 형상 병합 | 금속 장식·장갑 등 draw call 관리 | 피부/제복의 연속 토폴로지와 부위별 가중치 |
| 한 뼈에 고정된 정점 | 흉갑·팔 보호대·파우치 등 단단한 부품 | 관절 연결 천·피부의 다중 가중치와 변형 보정 |
| 목표 지점에서 관절각 계산 | 양손 파지·다리 IK의 설계 참고 | 사람의 팔꿈치 방향·관절 제한·접지·쇄골 보정 |
| 골격을 직접 갱신하는 애니메이션 | 외부 클립 없는 코드 모션 | 좌우 이동·앉기·사격·장전 사이의 접점 유지 |

단일 SkinnedMesh로 합쳤다고 draw call이 하나가 되는 것은 아니다. 재질 그룹, 그림자와 후처리 패스까지 별도로 비용을 계산해야 한다.

| [materials.js](../game/plan-f/materials.js) | 코드 생성 색·거칠기·노멀, 피부/천/머리/금속 재질·환경 반사 | 소재별 방향성·마스크·얼굴 색 분포. 금속용 긁힘·젖음 공식을 피부에 일괄 적용하지 않음 |

현재 구현은 이미 전신의 골격 위치와 동작 목표를 계산한다. 따라서 움직임을 전부 폐기할 필요는 없다. 우선 **표면 생성과 변형 구조를 교체하고 기존 목표/상태를 입력으로 받는 방향**이 가장 연결하기 쉽다.

## 6. 전신 형상 생성 설계

### 6.1 신체 비례·기준 자세·소켓을 하나의 명세에서 만든다

`HumanSpec` 같은 데이터에 키, 골반/어깨 폭, 흉곽/허리 깊이, 목 길이, 머리 크기, 상완/전완/허벅지/종아리 길이, 손/발 크기를 둔다. 이는 제안 명칭이며 현재 API가 아니다. 값은 기존 채택 원화에서 정하고 새 외형 설정으로 간주하지 않는다.

메시 치수, 뼈의 기준 위치, IK 길이, 어깨 견착점, 파우치와 장갑 부착점이 같은 명세를 사용해야 한다. 팔 메시만 길게 만들고 IK 길이가 남아 있으면 손 접점이 다시 틀어진다. 기준 자세는 겨드랑이를 설계하기 쉬운 완만한 A 자세를 제안하되, 최종 각도는 구현 시 고정해서 기록한다.

좌표는 현재 F를 유지한다. Y가 위, 인물 로컬 +Z가 전방이며 루트를 Y축으로 회전해 월드 오른쪽 +X/왼쪽 −X를 향한다. 정지 시 마지막 이동 방향을 유지한다. 인물의 앞을 카메라 방향으로 재정의하지 않는다. 좌우 이동은 루트 회전으로 처리하고, 손의 좌우 형상을 생성할 때만 반사 및 면 방향 처리를 적용한다.

### 6.2 원통 대신 위치·방향·비대칭이 있는 단면을 사용한다

제안하는 단면 데이터는 `center`, `orientation`, 좌우 폭, 앞뒤 깊이, 모서리 둥글기, 부위 마스크다. 샘플 점은 다음처럼 정의할 수 있다.

```text
p(s, θ) = center(s)
        + frame(s) × [width(s, θ) × sin(θ), 0, depth(s, θ) × cos(θ)]
        + anatomicalOffset(s, θ)
```

이 식은 새 생성기의 개념식이다. 현재 `loft`의 그대로인 API는 아니다. `frame`이 급격히 뒤집히지 않도록 중심선 프레임을 이어가며, 관절·실루엣 변화가 큰 구간에 단면을 더 둔다.

- 흉곽과 골반은 서로 다른 덩어리와 방향을 갖고, 허리에서 연결한다. 복부 전체를 한 강체로 기울이지 않는다.
- 어깨에는 쇄골·삼각근의 폭과 뒤쪽 볼륨을 둔다. 팔의 시작을 몸통 옆면에 꽂힌 원통처럼 처리하지 않는다.
- 상완/전완, 허벅지/종아리는 최대 굵기 위치와 앞뒤 곡률을 다르게 한다. 무릎과 팔꿈치의 관절 중심을 외피 중심과 구분한다.
- 손바닥은 앞뒤 비대칭, 손가락은 마디 길이·두께·벌림·엄지 방향을 별도 정의한다.
- 발은 뒤꿈치·발볼·발끝과 발바닥 접촉면을 갖게 한다. 발목점 하나의 높이만으로 신발 접지를 판단하지 않는다.

### 6.3 몸통의 분기는 별도 연결 면으로 만든다

목·어깨·골반은 독립적인 닫힌 타원체를 겹치는 것만으로 끝내지 않는다. 몸통 쪽에 목/팔/다리 개구부를 만들고 대응하는 경계 링을 연결하는 패치를 정의한다. 경계 정점의 순서와 개수, rest 위치, 가중치가 맞아야 한다. 가까운 점을 전역적으로 자동 weld하면 겨드랑이 양쪽이나 옷과 피부까지 붙을 수 있으므로, 연결할 경계를 명시한다.

처음부터 온몸이 하나의 메시일 필요는 없다. **같은 변형을 받아야 하는 피부/제복 구역은 이어지고, 단단한 장비는 독립적인 구조**면 된다. 소매 끝·허리띠·부츠처럼 실제 가려지는 경계에서는 분리할 수 있다. 노출되는 관절을 임시 구나 장갑으로 덮어 연속 변형이 완성됐다고 기록하지 않는다.

UV를 위해 복제한 경계 정점은 위치와 가중치를 공유하되, 부드러운 표면의 노멀은 이어준다. 금속 판 모서리와 봉제선처럼 의도한 경계는 노멀을 분리한다. 형상 끝막음, 삼각형 방향, 극점의 찌그러짐도 생성 규칙으로 다룬다.

## 7. 사람의 관절과 표면 변형

추천 골격은 `root → pelvis → spineLower → chest → neck → head`, 흉곽에서 양쪽 `clavicle → upperArm → forearm → hand`, 골반에서 `thigh → shin → foot → toe`로 이어지는 구조다. 팔 비틀림을 나눌 보조 뼈와 손가락 뼈는 필요한 부위에 추가한다. 개수부터 늘리기보다 어깨 들기·팔 회전·손목 파지·무릎 굽힘을 표현하는 역할을 먼저 정한다.

가중치는 생성 시 부위별로 작성한다. 단순히 가장 가까운 뼈를 고르면 몸 옆의 손이 골반에 붙거나 좌우 다리의 가중치가 섞일 수 있다. 해당 부위에 허용한 뼈 집합 안에서 거리와 단면 위치로 계산하고, 사용할 영향 수를 제한한 뒤 합을 1로 정규화한다. 단단한 판금은 한 뼈, 피부와 연결 천은 관절 주변에서 여러 뼈를 사용한다.

| 부위 | 기본 변형 | 추가 보정 |
|---|---|---|
| 어깨/겨드랑이 | 쇄골·흉곽·상완 사이 가중치 | 팔을 들 때 어깨 볼륨과 겨드랑이 접힘 보정 |
| 팔꿈치 | 상완/전완 연결 링의 가중치 변화 | 굽힘 안쪽 압축, 바깥쪽 길이·돌출 유지 |
| 전완/손목 | 전완 twist를 길이에 분산 | 손목만 회전해 팔이 꼬이는 현상 완화 |
| 허리 | 골반·척추·흉곽의 분산 회전 | 숙임 안쪽 압축, 바깥쪽 신장 |
| 골반/사타구니 | 골반·좌우 허벅지별 구역 가중치 | 깊은 앉기에서 엉덩이 체적·다리 사이 공간 유지 |
| 무릎 | 허벅지/종아리 연결 가중치 | 앞쪽 무릎 윤곽과 뒤쪽 접힘 |

기본 선형 스키닝만으로 큰 굽힘의 체적을 항상 유지할 수 있다고 가정하지 않는다. 필요한 관절에만 **각도에서 계산하는 보정 변위 또는 동일 토폴로지의 보정 형태**를 더한다. 매 프레임 새 메시를 생성하지 않고 기존 버퍼/뼈/보정량을 갱신한다. 생성한 기준 자세에서 bind하고, 기준 자세 변환과 현재 자세 변환을 구분한다.

## 8. 얼굴·머리·의상·손의 세부 방향

**얼굴:** SALTLINE에는 참고할 사람 얼굴 생성기가 없다. 현재 F의 단면 얼굴·코/뺨/눈두덩 변위가 출발점이다. 두개골, 턱, 광대, 안와, 코의 정면 폭과 측면 돌출을 각각 제어하고, 눈꺼풀은 안구에 맞는 경계와 두께를 갖게 한다. 입은 입술선과 주변 볼륨을 함께 설계한다. 정면에서만 눈·코·입을 붙여 놓는 방식으로 측면 인상을 해결할 수 없다. 표정은 얼굴 형태가 안정된 다음 단계다.

**머리카락:** 현재 띠형 면을 유지할 수 있으나 두피 덮개, 앞머리, 옆머리, 뒤쪽 덩어리의 겹침과 두께부터 맞춘다. 뿌리는 머리에 고정하고 길이 방향으로 지연을 늘린다. 재질의 결 방향은 머리 흐름을 따라야 한다. 전체 머리 그룹을 흔드는 것과 머리 끝만 늦게 따라가는 변형은 구분한다.

**의상:** 제복은 신체 표면에서 바깥으로 띄운 외피를 만들되, 관절마다 여유와 접힘을 설계한다. 장갑판은 관련 뼈에 단단히 붙이고 연결 천만 변형한다. 흉갑은 흉곽, 벨트/파우치는 골반, 팔 보호대는 전완을 기준으로 한다. 실제 의상 구조에 맞춰 어깨판의 흉곽/상완 추종을 결정한다. 팔을 굽혀도 금속 판이 고무처럼 휘어서는 안 된다.

**망토:** 현재의 정점 흔들림과 바닥 높이 제한은 초기 표현이다. 후속에는 어깨 고정, 길이 유지, 머리·흉곽·골반·허벅지를 근사한 충돌체를 추가한다. 화면에서 천이 움직인다는 이유로 천 충돌이 구현됐다고 기록하지 않는다.

**손:** SALTLINE을 가장 직접적으로 적용할 부위다. 손바닥 곡면, 세 마디 손가락, 별도 엄지와 손가락 사이 연결을 생성하고 `총 손잡이`, `총열 받침`, `탄창 파지`, `노리쇠 조작`, `놓기`를 파지 프리셋으로 둔다. 각 프리셋은 같은 토폴로지와 정점 순서를 유지해야 형태 보간이 가능하다. 변형량이 큰 경우 손가락 뼈 회전을 쓰고, 패드 눌림 같은 작은 변화만 형태 보간으로 보완한다.

손목 소켓 일치는 손가락 접촉 완료가 아니다. 총 손잡이·탄창의 접촉면과 엄지/검지의 공간을 별도로 확인한다. 손 크기·파지 프리셋·무기 소켓이 같은 손 좌표 규약을 사용하게 한다.

## 9. 재질과 조명에서 가져올 것

SALTLINE은 `Gg`에서 GPU 렌더 타깃으로 색·ORM·노멀맵을 생성하고 재사용한다. 손은 생성 곡면의 정점 색과 장갑 직물 재질을 함께 사용한다. 총은 금속/폴리머별 재질과 별도 세부 셰이더를 적용한다. 코드 생성이라는 공통점은 가져오되, 플랜 F의 기존 CPU DataTexture 경로를 GPU 방식으로 바꾸는 일은 측정 후 결정한다.

| 소재 | 큰 형상에서 해결 | 표면에서 해결 |
|---|---|---|
| 피부 | 얼굴/관절 볼륨, 눈꺼풀·입술·귓바퀴 | 약한 피부색 변화·거칠기·미세 요철. 금속성 0을 기본으로 검토 |
| 제복/장갑 | 소매 여유·커프·큰 주름·패드 | 직물 결·봉제선·마모와 눌림 |
| 갑옷/총 | 판 두께·모서리·단차·접합 | 도장·금속·긁힘·오염·거칠기 구역 |
| 머리카락 | 두피 덮개·머리 덩어리·겹침 | 길이 방향 결, 방향을 따르는 하이라이트 |

노멀맵은 실루엣을 바꾸지 못하므로 코, 손가락 마디, 옷자락의 큰 주름을 대신하지 못한다. 트라이플래너 투영은 불규칙한 장비에 편리하지만, 직물·머리처럼 방향이 중요한 재질은 생성 UV를 우선한다. 스키닝 전 기준 좌표 또는 안정된 UV로 패턴을 고정해 움직일 때 질감이 미끄러지지 않게 한다.

색 텍스처와 수치 텍스처의 색 공간을 구분하고, 현재 r187 셰이더 구조에 맞춰 작성한다. SALTLINE r180의 셰이더 문자열 치환을 그대로 복사하지 않는다. 피부 산란이나 이방성 모발은 별도 추가 기능이며 원본에서 전신용 해법을 얻었다고 간주하지 않는다.

형상 판단은 중립적인 광원과 무광 재질에서도 할 수 있어야 한다. 그다음 기존 환경 반사·그림자·AO·블룸을 켜 비교한다. 강한 후처리로 관절 틈이나 얼굴 비례를 가리는 것을 완료 기준으로 삼지 않는다.

## 10. 기존 이동·사격·장전에 연결하는 순서

```text
고정 스텝: 입력 → 이동/탄약/장전/반동 상태 → 접지 상태
표시 계산: 골반·흉곽 자세 → 어깨/견착 프레임 → 총 자세
          → 양손·탄창·발 목표 → 도달성 조정 → 팔/다리 관절
          → 손가락 파지·표면 보정 → 머리/천의 후행 반응
          → 최종 소켓·총구·장비 변환 → 렌더
```

상태를 진행시키는 함수와 자세를 읽는 함수를 분리한다. 일시정지 중 카메라나 자세 표시를 다시 계산해도 탄수·장전 큐·접지 이력이 중복 진행되면 안 된다.

1. **접지:** 발이 닿는 순간의 월드 위치를 저장하고 지지 구간에는 유지한다. 발을 옮기는 구간에서 다음 위치로 회수한다. 가감속·방향 전환 시 접지를 풀거나 발을 다시 놓는 규칙을 둔다. 현재 `sampleStep`의 lift/pitch 곡선은 회수와 발 굴림의 시작점으로 재사용한다.
2. **도달성:** 어깨–손 목표 거리와 팔 길이, 골반–발 거리와 다리 길이를 먼저 맞춘다. 목표가 도달 불가이면 총/어깨/골반을 허용 범위 안에서 조정하고 최종 끝점을 제한한다. 관절만 계산상 clamp하고 실제 손은 먼 목표에 두면 팔과 손 사이가 벌어진다.
3. **관절 방향:** 팔꿈치·무릎의 굽힘 방향을 명시하고, 완전 펴짐 근처에서 갑자기 뒤집히지 않게 이전 안정 방향과 제한각을 사용한다. 방향 벡터 하나만으로 전완의 비틀림까지 정하지 않는다.
4. **견착:** 어깨 pocket에서 총을 배치하고 같은 총 변환에서 양손·탄창·총구를 계산한다. 총과 팔이 서로의 결과를 다시 입력으로 삼는 순환을 피한다. 도달성 수정이 필요하면 제한된 횟수의 명시적인 보정 단계로 수행한다.
5. **장전:** 이미 있는 2.2초/2.8초 시간·분리/삽입 큐·손에 붙는 탄창 변환을 유지한다. 손가락 파지와 손목/전완 회전을 추가한다. 탄창은 한 구간에 소유자가 하나이며, 손에서 총으로 돌아갈 때 위치·회전이 이어져야 한다.
6. **반동:** 총→흉곽→머리의 시간차, 다리와 골반의 작은 하중 반응을 유지한다. 각 부위에 독립 난수를 더해 접점을 깨는 대신 공유된 반동 상태를 사용한다.

카메라 슬라이더·이동 방향 시선·C 앉기·좌우 이동·0.25×·정지와 연결한다. SALTLINE의 카메라 전용 무기 흔들림 계수를 그대로 복사하지 않고, 전신 무게 이동과 접점을 기준으로 진폭을 다시 조정한다.

## 11. 후속 코드 작업 단위와 순서

다음 경로는 **제안이며 아직 생성하지 않았다**. 기존 `createLian()`의 `root/muzzle/ejection/pose` 반환 계약을 유지하는 어댑터부터 두면 미리보기와 효과 연결의 변경을 줄일 수 있다.

| 순서 | 제안 작업 | 기존 코드 연결 | 다음 단계로 넘길 조건 |
|---|---|---|---|
| 1 | `human/spec.js`, `human/surface.js`: 비례·단면·분기 패치 | `model-build.js`, `geometry.js` | 중립 자세의 정면·측면·후면에서 비례·목/어깨/골반 연결 확인 |
| 2 | `human/rig.js`, `human/weights.js`: 코드 골격·가중치 | `weapon-pose.js`, `model.js` | 팔 들기·팔꿈치·허리·깊은 앉기에서 표면 연속성과 도달성 확인 |
| 3 | `human/face.js`, `human/hair.js`: 얼굴·머리 형상 | 기존 얼굴/머리 생성 구간 | 채택 원화의 인상과 실루엣 확인, 표정은 후순위 |
| 4 | `human/clothing.js`: 제복·갑옷·장비 | 기존 소재·판금·망토 | 장갑 강체성, 허리/무릎/어깨의 간섭 확인 |
| 5 | `human/hands.js`, `human/pose.js`: 손 프리셋·기존 상태 어댑터 | `reload-pose.js`, `simulation.js`, `motion.js` | 서기·이동·앉기에서 파지·견착·일반/빈 장전 연결 |
| 6 | 재질 미세화·머리/천 후행·성능 정리 | `materials.js`, 기존 렌더러 | 실제 화면 크기와 확대 모두에서 품질·비용 확인 |

가장 먼저 만들 검토 단위는 **어깨–상완–팔꿈치–전완–손의 한쪽 연속 외피**를 기존 총 목표에 연결한 것이다. 이 구간에서 단면 생성·분기 접합·스키닝·손 파지를 함께 판단한 뒤 전신으로 확장한다. 다만 최종 비례 기준은 1단계 전신 명세를 먼저 정해 두어야 한다.

리그 교체 전 실제 변경 시점의 소스를 다음 버전 기록에 보존하고 기존 A~E·GLB와 과거 결과를 유지한다. 새 모션마다 사이트를 만들지 않고 기존 `#/samples/characters/clone_01?plan=f`에 연결한다. 이 분석 문서를 새 시각 에셋 버전으로 등록하지 않는다.

## 12. 사용자가 확인할 품질 기준과 성능 항목

아래는 **향후 검수 항목이며 이번에 실행한 검사가 아니다**. 기존 “검증은 내가할게 개발만해봐” 지침에 따라 자동 테스트·구문/문서/목록 검사·브라우저 캡처는 실행하지 않았다.

| 장면 | 확인할 내용 |
|---|---|
| 무광 중립 자세, 전후좌우·사선 | 사람 비례, 어깨/골반 연결, 얼굴 측면, 머리/옷 실루엣 |
| 팔 들기·앞으로 뻗기·팔꿈치 굽히기 | 겨드랑이 구멍·어깨 함몰·손목 끊김·전완 꼬임 |
| 앉기 전환·최저 자세 | 골반 체적, 사타구니/무릎 접힘, 장갑·파우치·총 간섭 |
| 좌우 이동·출발·정지·반전 | 발 미끄러짐, 무릎 뒤집힘, 마지막 방향 유지 |
| 단발·연사·복귀 | 견착과 양손 접점, 총구 일치, 몸/머리 반응 |
| 일반/빈 장전, 0.25×·정지 | 손가락 파지, 탄창 소유권 전환, 몸통/파우치 통과 여부, 시간 큐 |
| 카메라 변경·정지/재개 | 형상·접점은 동일, 시간 상태는 중복 진행하지 않음 |
| 기본 표시 크기·확대 | 멀리서 인물 구별, 가까이서 얼굴과 관절 품질 |

성능은 생성 시간, 삼각형/정점 수, 재질별 draw call, 뼈 수, 동적 정점 갱신량, 텍스처 메모리, 프레임 시간으로 나눠 기록한다. 현재 F 얼굴은 64×64 셀을 쓰는 반면 인체 연결은 별도 파츠인 상태다. 면 수를 일괄 늘리기보다 얼굴 윤곽·손·관절에 배분하고 보이지 않는 장식의 비용을 줄이는 방향을 검토한다.

매 프레임 전신 토폴로지를 재생성하거나, 모든 정점의 노멀을 CPU로 다시 계산하는 방식을 기본으로 삼지 않는다. 골격 변형은 GPU에 맡기고 CPU 갱신이 필요한 천/보정 구간은 범위를 좁힌다. 초기 캐시에는 품질·치수·재질 시드를 포함하며 서로 다른 체형의 mutable 버퍼를 공유하지 않는다. 리소스 해제도 기존 미리보기 생명주기에 연결한다. 목표 프레임이나 모델 수를 이번 정적 조사만으로 달성했다고 보고하지 않는다.

## 13. 구현 판단

**우선 적용:** 단면 기반 손·인체 곡면, 치수와 소켓의 공동 정의, 코드 생성 골격, 부위별 재질/정점 마스크, 손 위치·회전 키프레임, 사건별 반동 채널.

**사람용으로 새로 작성:** 어깨·골반 분기 토폴로지, 다중 뼈 가중치, 큰 굽힘 보정, 얼굴/머리 미감, 손가락 접촉, 월드 접지와 의상 간섭.

**그대로 옮기지 않을 것:** 카메라 종속 손/총 배치와 FOV 보정, 로봇용 단일 뼈 가중치를 피부 전체에 적용하는 방식, 원본 숫자에 맞춘 손목 위치, 원본 r180 셰이더 치환, 화면 가림만으로 성립하는 동작.

이 설계의 성공 기준은 “코드로 사람이 표시된다”를 넘어 **채택 인물의 비례와 인상이 유지되고, 서기·앉기·이동·사격·장전에서 사람의 표면과 접점이 이어지는가**다. 이번 문서는 그 구현 경로를 정리했으며 새 형상·동작의 완성도는 아직 판단하지 않는다.
