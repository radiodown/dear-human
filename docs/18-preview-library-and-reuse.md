# 18. 통합 샘플 사이트와 산출물 재사용

[문서 목록](../README.md) · 캐릭터·무기별 통합 미리보기는 사용자 요구사항이다. 현재 채택 원화와 자체 WebGL 파츠 모션 시험을 같은 앱에서 제공한다. 실제 게임 씬·Phaser·Spine은 아직 연결하지 않았다. 외형은 [23](23-character-appearance-review.md), 실제 시험 결과는 [24](24-motion-rig-test.md), 목록·검사/조회 CLI는 [20](20-agent-automation.md)을 따른다.

## 1. 기본 규칙

**미리보기 사이트는 하나로 유지하고, 캐릭터·무기·갑옷·효과마다 고정 샘플 페이지를 둔다.** 모션 하나를 만들 때마다 새 사이트나 임시 데모를 만들지 않는다. 같은 대상의 새 결과는 해당 페이지의 모션·파츠·버전에 추가한다.

첫 캐릭터 원화·파츠·무기·모션을 실제 제작할 때 공통 샘플 사이트를 함께 구축한다. 이후 에셋 작업의 완료 조건에는 **산출물 저장·목록 등록·해당 페이지에서 확인 가능**까지 포함한다. 게임 1스테이지가 완성될 때까지 미루지 않는다.

제작 전에 기존 목록·채택 버전·검수 기록을 먼저 확인한다. 활용 가능한 결과가 있으면 재사용하고 요청이 달라진 부분만 수정한다. 사용자가 새 시도를 요구하면 같은 요청이더라도 새 시도로 기록한다.

## 2. 페이지 구성

| 페이지 | 보여줄 내용 |
|---|---|
| 샘플 홈 | 대상 목록·썸네일·완성도·최근 변경·검수 상태 |
| 캐릭터 | 기준 이미지, 분리 파츠, 리그, 모든 준비된 모션, 장착 무기·갑옷 조합 |
| 무기 | 분리 본체/탄창·피벗·손잡이·총구, 기본 캐릭터의 파지·반동·사격·일반/빈 장전 |
| 갑옷 | 부위 파츠·기본 복장과 비교·가림·soft/rigid 모션·무기 간섭 |
| 효과 | 화염·탄도·혈액·진액·폭발·파편·숫자의 단독 재생과 실제 판정 적용 |
| 적 | 접근·피격 등급·약점·일반/치명/폭발 사망 비교 |
| 스토리 장면 | 대화·컷신 큐, 전체/노드 재생·중간 스킵·완료 상태 비교 |

캐릭터 페이지 안에서 모션 목록을 선택한다. 걷기·정지 사격·이동 사격·피격이 같은 대상 페이지에 모여 있어야 한다. 원본·현재 버전·채택 버전과 최대 두 버전의 비교를 제공한다.

썸네일 목록은 정지 이미지 위주로 표시하고, 선택한 대상만 재생한다. 여러 페이지가 동시에 리그·입자를 계속 돌리지 않게 한다. 모든 모션의 동시 재생은 검토할 때 선택하는 제한된 보기로 둔다.

## 3. 안정적인 진입 주소

같은 웹 앱의 예시 해시 경로다. 현재 접속 가능한 사이트 URL이라는 뜻은 아니다.

```text
#/samples
#/samples/characters/clone_01
#/samples/characters/clone_01?motion=walk&weapon=m16_basic
#/samples/weapons/m16_basic
#/samples/weapons/m16_basic?motion=reload_empty
#/samples/armor/<appearance_id>
#/samples/fx/<fx_id>
#/samples/enemies/swarm_creature_melee
#/samples/stories/stage_01_intro
#/samples/stories/stage_01_outro
```

대상 ID는 버전이 바뀌어도 유지한다. 필요하면 rev와 비교 대상을 URL에 넣어 동일한 결과·설정으로 돌아올 수 있게 한다. 새 모션마다 HTML 파일과 배포 프로젝트를 복제하지 않는다.

## 4. Motion Lab과 공유

목표 구성에서 샘플 사이트는 Vite·Phaser 앱의 라이브러리 화면이다. 현재 구현은 HTML/CSS/JS와 공유 JavaScript/WebGL 리그이며 향후 게임 씬 연결은 아직 하지 않았다. 라이브러리 UI가 대상·버전·모션·장비를 고르고, 실제 재생은 MotionLabScene과 CharacterView/RigAdapter·무기·외형·FX 코드를 재사용한다.

단발·연사·이동·방향 전환·피격, 명중도·bloom·스침/일반/치명/약점 비교, 폭발 거리·벽 가림·사망 비교, 머리·바스트 on/off, 원래 크기·확대·느린 재생, 소켓·관절 표시를 공통 컨트롤로 제공한다. 캐릭터·무기별 페이지는 이 공통 화면에 데이터만 다르게 넣는다.

원화만 있으면 이미지·파츠 보기를 제공하고 리그가 준비되기 전에는 동작 재생을 미지원으로 표시한다. 참고 GIF와 실제 런타임 리그의 재생을 구분한다. 임의 흔들림을 넣은 정지 이미지로 실제 모션이 구현됐다고 표시하지 않는다.

사이트 제작·로컬 실행·정적 빌드는 [04](04-technical-architecture.md)의 웹 구성을 따른다. 개발 중에는 로컬 미리보기를 계속 갱신하고, 공유 가능한 배포본을 만들 때도 같은 소스·목록을 사용한다.

[19](19-combat-feel-and-damage.md)의 타격감 프리셋도 기존 사이트의 대상별 페이지에 추가한다. 실제 CombatResolver 결과로 숫자·소리·입자·카메라를 비교한다. 결과만 강제로 표시하지 않고 산포·시드·영역·치명타 설정을 저장해 재현한다.

[21](21-story-and-skipping.md)의 스토리 샘플은 같은 StoryRunner·대화 UI·리그·카메라 큐를 격리 세션에서 실행한다. 본편 플래그·읽음 기록을 변경하지 않고 관람/스킵 후 상태를 비교한다. 장면 목록은 별도 StoryRegistry를 사용하며 현행 asset_index의 시각 에셋 kind는 유지한다. 텍스트 수정으로 캐릭터·무기를 다시 생성하지 않는다.

[22](22-weapon-reloading.md)의 일반/빈 장전은 기존 캐릭터·무기 페이지에 추가한다. 같은 ReloadController·상체/손 목표·탄창 뷰를 사용하며 탄수·예비탄·시간·큐·접점을 확인한다. 이동·반전·피격·갑옷·정지/재개·취소를 비교하고 느린 재생·되감기는 격리 상태에서 수행한다. 장전 하나마다 사이트나 캐릭터 원화를 새로 만들지 않는다.

## 5. 목록과 버전 메타데이터

AssetRegistry가 읽는 asset_index.json을 사이트의 진입 목록으로 둔다. 종류, 논리 ID, 표시명, 상태, 버전, 사용 가능한 보기·모션, 관련 대상과 산출물 경로를 기록한다. 데이터 형식은 [07](07-data-and-assets.md)에 예시를 둔다.

생성 이후의 각 버전에는 다음 정보를 연결한다.

- 원본·파츠·리그·아틀라스·모션·무기 정의·검수 이미지의 실제 경로와 콘텐츠 해시.
- 사용 도구·모델·버전·생성 설정·프롬프트 원본 위치·지원되는 경우 seed.
- 기본 입력·캐릭터 리그·무기·갑옷·효과의 의존 버전.
- 검수 결과·문제·채택 여부·실제 생성/보정 시간·기록 가능한 실제 비용.
- 단발/연사·좌우·표시 크기 등 해당 미리보기를 재현할 설정.

없거나 측정하지 않은 값은 null 또는 미기록으로 둔다. 원본 프롬프트나 전체 대용량 데이터를 채팅에 매번 붙이지 않고 경로와 짧은 변경 요약으로 참조한다. 비밀 키나 접속 자격 증명은 기록하지 않는다.

## 6. 중복 생성과 변경 범위

1. 대상 ID와 원하는 파츠·모션을 기존 목록에서 찾는다.
2. 입력 파일 해시·레시피·도구/모델·설정이 같은 기존 결과와 검수 상태를 확인한다.
3. 재사용할 결과와 변경할 의존성을 정한다. 필요하면 새 버전을 만든다.
4. 실패한 부위나 동작만 다시 생성·보정하고 공통 파츠·리그·무기는 유지한다.
5. 산출물 구조·참조를 검증한 뒤 목록과 페이지를 갱신한다.
6. 대화에는 페이지 진입점·변경 항목·남은 문제만 짧게 전달한다.

같은 레시피가 항상 같은 이미지를 생성한다는 보장은 아니다. 레시피 키는 이미 만든 결과를 찾는 용도, 콘텐츠 해시는 실제 파일이 같은지 확인하는 용도다. 새 버전을 만들 때 기존 채택 산출물을 덮어쓰지 않는다.

무기 이미지 변경은 해당 무기와 관련 장착 샘플에만 영향을 준다. 리그 변경은 이를 사용하는 조합의 검수 기록을 오래된 결과로 표시한다. 예전 영상은 보존하되 최신 런타임의 검증 결과로 재사용하지 않는다. 관련 없는 캐릭터·모션을 다시 생성하지 않는다.

## 7. 갱신·성능·검수

목록은 실제 파일·종속 ID 검증을 통과한 뒤 갱신한다. 불완전한 작업은 draft/failed 상태로 남기고 정상 버전의 진입점을 깨뜨리지 않는다. 생성 원본·실패 시안은 원본 보관 경로에 두고 웹에는 필요한 결과만 제공한다.

같은 해시의 이미지·리그는 중복 로드·복사하지 않는다. 선택 변경 시 이전 재생·타이머·입자를 정리하고 캐시는 상한 안에서 재사용한다. 탭 숨김·페이지 이탈 시 재생을 멈춘다. 자동 영상 출력·전 프레임 스크린샷·모델 호출은 매 방문마다 실행하지 않는다.

첫 실제 산출물부터 페이지를 확인하고, 새 모션 추가가 기존 모션·캐릭터·무기 샘플을 지우지 않는지 검사한다. 사이트의 검수 상태와 아트 채택 버전은 별개로 기록한다. 실제 구현과 검증은 향후 수행하며 [08](08-feasibility-and-qa.md)의 샘플 라이브러리 검수를 따른다.
