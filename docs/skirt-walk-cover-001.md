# 걷기 스커트·허벅지 덮임 보정 · skirt_walk_cover_001

사용자 요청: “걸을때 스커트 밖으로 허벅지쪽이 빠져나가는게 이상해. 스커트가 다리를 덮고있지않고있는 느낌이야”. [같은 이동 페이지](http://127.0.0.1:4173/#/samples/characters/clone_01?motion=walk)에서 공통 파츠 코드로 적용한다.

기존 `skirtPanelPoint()`는 앉아쏴의 양만 사용했다. 걷기에서는 골반에 붙은 스커트가 다리 움직임을 받아주지 않았고, 허벅지의 둥근 윗단은 전체 다리와 함께 회전했다. 분리 파츠의 윗단이 스커트 옆으로 드러나면서 허벅지가 옷 밖에서 시작하는 모습이 생길 수 있었다.

허벅지의 상단은 골반 회전에 붙이고, 원본 UV v=.28까지 실제 허벅지 방향으로 부드럽게 연결했다. 고관절 중심·무릎 중심과 뼈 길이는 그대로이며, 허벅지 원본 전체를 확대/축소하거나 새 이미지로 바꾸지 않았다. 대기와 완전히 앉은 자세에서는 이 추가 연결이 사라진다.

걷기·달리기의 스커트 앞/뒤 패널은 양쪽 허벅지 중 앞·뒤로 가장 나온 방향을 받아 벌어진다. 다리가 교대해도 같은 바깥 의상이 덮도록, 한 패널을 특정 다리에만 붙이지 않았다. 상단 벨트와 패널 위쪽 행, 두 패널이 만나는 u=.52는 같은 위치에 유지한다. 기존 앉아쏴의 접힘 경로는 그대로 두고 걷기 반응을 앉는 양에 따라 줄인다.

처음에는 다리 각도대로 아랫단을 들어 올려 덮임이 부족했다. 최종 보정은 앞뒤 벌어짐을 따르면서 수직 들림은 25%만 전달하고, 바깥 아랫단에 최대 5 논리 단위의 아래 늘어짐을 더했다. 윗단과 중앙 연결선에는 이 늘어짐을 적용하지 않는다. 기존 허리/옷자락 추가 반응과 별개로 옷의 기본 덮임은 유지한다. 이는 기존 측면 UV를 변형하는 작성 규칙이며 실제 중력·3D 천 충돌 계산은 없다.

`game/animation/waist.js`의 `SKIRT_WALK`, `thighRootOffset()`와 `walkingSkirtPoint()`를 공통 WebGL 렌더러에서 사용한다. 실제 게임용 리그와 미리보기는 같은 계산을 쓴다. 원본 PNG·리그 정의/UV 목록·머리/몸통 연결·총구/대기/사격·조절/저장·플랜 B/C·GIF는 이번 변경 범위에 포함하지 않았다.

필요한 두 JS 구문 검사와 짧은 메시 연결 확인을 수행했다. 벨트 부착 행·두 패널 경계·두 다리를 교대한 바깥 덮임은 수치 정밀도 범위에서 이어졌고, 고관절/무릎 중심의 추가 이동은 0이었다. 대기와 완전히 앉은 자세의 스커트 좌표는 보존 소스와 같았다. [수치 기록](../art/characters/clone_01/motion/rig_005/tests/skirt_walk_cover_001/garment-smoke.json).

Chrome에서 양쪽 다리가 앞으로 나온 걷기 두 시점과 달리기의 같은 자세를 고정해, 변경 전 스커트/허벅지 표시와 변경 후를 비교했다. 실제 보행 코드/시간을 바꾸지 않고 옷과 허벅지 메시 표시만 전환한 비교다. 짧은 재생도 확인했다. [비교 기록](../art/characters/clone_01/motion/rig_005/reviews/skirt_walk_cover_001/browser.json) · [걷기 재생](../art/characters/clone_01/motion/rig_005/reviews/skirt_walk_cover_001/walk-playback.json). 아랫단 들림이 과했던 첫 비교 결과도 `first_drape_trial`에 보존했다.

변경 전 허리·렌더러·카메라 참조 소스 3개는 `runtime_snapshot_before_skirt_walk_cover_001`에 보존했다. 실제 수정 소스는 허리와 렌더러 두 개다. 레시피/인계와 tests/reviews는 `skirt_walk_cover_001`로 분리하며 과거 검사/`untested` 기록은 그대로다. 전체 테스트나 문서/목록 검사는 실행하지 않았다. 모든 프레임의 실제 알파 덮임, 큰 보폭/수동 설정과 앉기 전환에서의 가림·장식 변형은 사용자 검수 대기다.
